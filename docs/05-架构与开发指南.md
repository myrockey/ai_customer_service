# 智能客服系统 - 架构与开发指南

> 面向开发者的代码级指南：总体架构、目录结构、模块职责、请求链路、开发规范、验证命令与常见坑。

### 3.1 启动流程（main.go）

1. `logger.Init("json")` → 结构化日志；
2. `telemetry.InitTracer()` → OpenTelemetry（OTEL_* 环境变量，默认关闭）；
3. `config.LoadConfig` + `ValidateConfig`（MySQL DSN、Agent URL 必填）→ `InitDB`；
4. `auth.InitAuth` → 从 `tenants` 表加载运行时租户；
5. `crypto.InitRSA(RSA_PRIVATE_KEY_PATH)` → 首次启动自动生成 RSA 密钥对并持久化（默认 `data/rsa_private.pem`，compose 挂载 `./data` 卷）；
6. `cache.Init()` → **Redis 强制依赖，连接失败即启动失败（fail-fast）**；
7. 后台协程：① 3s 后预热所有启用租户（`PrewarmTenant`）；② 每小时清理 Token 黑名单（Redis TTL 自动过期，函数保留为空实现）；③ 每日消息归档（`ArchiveOldMessages`，保留期 `CS_MSG_RETENTION_DAYS`，默认 90 天 → `messages_archive`）；
8. `router.SetupRoutes(r)` → 监听 `:8080`。

### 3.2 中间件链（router.go）

```
CORS 白名单 → Tracing(OTel) → Trace(X-Trace-Id) → PrometheusMetrics → RequestLogger → StatusCode
```

- **CORS**：读取 `CORS_ALLOW_ORIGINS`（逗号分隔）；未配置默认仅放行 `localhost:8080 / 127.0.0.1:8080`。iframe 同源嵌入不受影响，第三方 XHR 直连需显式配置。
- **StatusCode 归一化**：`body.code >= 500 → 500`；`400/401/403/404/405/409/429` 透传；其余 4xx → 400。`/ws/*` 与 `/metrics` 跳过。
- **Trace**：生成/透传 `X-Trace-Id`，响应头回写，全链路（Go→Agent）透传。
- 所有 handler 统一返回 `{code, msg, data}`，业务方按 `body.code` 判断，HTTP 语义同时准确。

### 3.3 鉴权体系

**Token 结构（自研 HMAC，非标准 JWT）**：

```
token = base64url(payload) . HMAC-SHA256(payload, sign_key)
payload = {"tid": 租户ID, "exp": 过期时间, "nonce": 16字节随机数}
sign_key = 租户 app_secret 的 sha256 哈希（app_secret_hash）
```

- 每次签发含随机 `nonce`，防重放；`token_ttl` 默认 24h（config.yaml `auth.token_ttl`）；
- 角色**不写入 token**：由 `tenants.is_platform_admin` 在服务端判定（平台管理员 / 租户管理员 / 业务用户）；
- **黑名单**：登出/刷新后旧 token 写入 Redis `cs:tok:bl:{token}`（TTL=剩余有效期）；Redis 查询失败按「已拉黑」处理（fail-closed，登出 token 不允许复活）。

**登录与换票**：

1. `GET /api/auth/public-key` → 下发 RSA 公钥；
2. `POST /api/auth/token`：`{app_key, app_secret, encrypted}`。管理端登录传 `encrypted: true`（RSA-OAEP 加密 app_secret，防明文抓包）；第三方明文接入可 `encrypted: false`；
3. 返回 `{token, tenant_id, expires_in, is_platform_admin}`；
4. **防爆破**：Redis `cs:login:fail:{ip:app_key}` 连续失败 5 次锁 10 分钟（429）；Redis 故障时拒绝登录（fail-closed）。
5. `POST /api/auth/refresh`（旧 token 拉黑）、`POST /api/auth/logout`、`PUT /api/auth/password`（改自己密钥，改后旧 token 因签名密钥变化自动失效）。

**中间件**：`UserAuth`（校验 token + user_id 归属当前租户，user_id 约定 `{tid}:{uid}`）、`AdminAuth`、`PlatformAdminOnly`（仅平台管理员）、`BusinessOnly`（平台管理员不可访问租户业务数据，仅放行平台级 Prompt）、`InternalAuth`（Go↔Agent 用 `X-Internal-Token`）。

### 3.5 关键设计

- **模型配置三级（实际实现）**：
  1. **平台默认** = 平台管理员租户 `t_admin` 自身的模型配置（tenants 表 BYOK 字段），前端「平台模型配置」页复用租户配置组件（`platform: true`）；
  2. **平台代配租户**：`GET/PUT /api/admin/tenants/:tid/model-config`；
  3. **租户自配（BYOK）**：`GET/PUT /api/business/model-config`，支持跟随平台或自定义。
  保存成功后 Go 通过 `cache.Publish("cs:model:cache:invalidate", {tenant_id, scope, ts})` **Redis 广播**失效（HTTP 直调已移除）；Agent 侧另有「配置签名对比」兜底（≤10s 最终一致，见 [06-多实例扩展](./06-多实例扩展与Redis缓存失效广播方案.md)）。
- **模型提供商**：`model_providers` 表仅存元信息（provider_key/名称/默认模型/Base URL/类型 chat|embedding），**不存 API Key**；租户 Key 存 `tenants.model_api_key / embedding_api_key`（AES 密文）。
- **密钥安全**：API Key AES 加密存储、不返显、掩码显示；`PROD_MODE=true` 时强制要求 `MODEL_KEY_ENCRYPT_KEY`（compose 用 `${MODEL_KEY_ENCRYPT_KEY:?}` 缺失即拒绝启动）。
- **租户隔离**：所有业务表带 `tenant_id` + 复合索引；查询强制带租户条件；Agent 侧知识库按 `kb_{tenant_id}` 集合隔离；用户侧 `user_id/thread_id` 约定 `{tid}:{uid}`，中间件校验归属。
- **消息归档**：每日将超过保留期（默认 90 天）的 `messages` 迁移到 `messages_archive`（`CS_MSG_RETENTION_DAYS` 可调）。
- **WebSocket 限流**：单 IP ≤10 连接、单 user_id ≤3 连接、单用户 ≤5 条消息/秒（滑动窗口）。

### 4.1 启动流程（lifespan）

1. PG 异步连接池（`AsyncConnectionPool`，min 2 / max 10）+ 独立 checkpoint 连接（`SafeAsyncPostgresSaver` 串行化并发写）；
2. `verify_agent_tables` 校验表存在（**DDL 唯一来源是 `deploy/init/postgres/init.sql`**，代码不建表）+ `seed_default_prompt` 播种默认 Prompt；
3. Qdrant 客户端 + 平台默认 Embedding（不可用降级启动，不阻塞服务）+ 文本切分器；
4. 平台默认对话模型（DB 单一数据源，懒构建重试）+ 工具注册；
5. 启动会话回收后台任务（`SESSION_RETENTION_DAYS` 默认 7 天、`SESSION_CLEANUP_INTERVAL` 默认 21600s）；
6. Redis 客户端初始化并 `ping()`，**失败即启动失败（fail-fast）**，随后启动失效广播订阅任务；
7. 知识库索引 worker（`KB_INDEX_WORKERS` 默认 2）：启动时先 `requeue_pending` 兜底重扫 `status=0` 遗留记录。

| 路由 | 说明 |

### 4.3 Agent 构建要点

- `build_agent(system_prompt)` 按租户配置动态构建 LangGraph Agent；`get_tenant_agent` 带缓存，配置变更时 `rebuild_tenant_agent`；
- 中间件仅挂载 `content_guard`（敏感词拦截）；`auto_signature` 为保留空实现，**不再挂载**；
- 知识库检索：租户集合 `kb_{tenant_id}` → Qdrant；Embedding 支持 local/dashscope 双模式（环境变量切换）；
- 配置失效双通道：Redis 广播即时失效 + `_agent_sigs` 配置签名懒检查（10s TTL，广播丢失兜底）；
- 并发配额：流式/恢复前 `check_concurrent_sessions`（`tenants.max_concurrent_sessions`，0=不限）。

### 4.4 知识库异步索引（P2-5）

```
上传（routers_kb.kb_upload）
  → 提取文本（kb_parser）→ 原文件落盘共享卷 /kb_files/{tenant}/{doc_id}{ext}
  → DB 登记 status=0 → Redis 队列 cs:kb:index:queue（lpush）
  → kb_index_worker 消费：分片 → embedding → Qdrant → status=1（失败记 error_msg）
```

- 单文件大小上限：平台设置 `kb_max_file_mb`（默认 10MB，nginx `client_max_body_size 110m` 兜底）；
- 下载/预览走 nginx 静态 `/kb_files/`（路径含随机 doc_id + 租户前缀，防枚举）；
- `POST /api/admin/kb/index` 可手动索引入队（空 body=全部待索引/失败文档，doc_ids=指定文档）。

### 4.5 用量计量（P1-1）

- 对话/流式/恢复完成后统一 `record_token_usage`：记录模型名、来源（platform/custom）、输入/输出/总 token、**按发生时单价快照的费用**（价格调整不影响历史账单）；
- 单价来自 `tenants` 表：`chat_input_cache_price / chat_input_price / chat_output_price / embedding_price`（元/百万 tokens，0=未定价）；
- 数据落 PG `token_usage`，Go 后台 `GET /api/admin/token-usage` 提供报表（平台全览 / 租户仅自身）。

## 5. 数据库分工（表归属原则）

| 数据 | 库 | 表 | 说明 |
|------|----|----|------|
| 租户/账号 | MySQL | `tenants` | app_key / app_secret_hash / BYOK 模型字段 / 单价 / 配额 |
| 模型提供商 | MySQL | `model_providers` | 仅元信息（provider_key/名称/默认模型/Base URL/类型），**不存 Key** |
| 平台配置 | MySQL | `platform_config` | key-value（预留；平台默认模型实际为 t_admin 租户配置） |
| 会话消息 | MySQL | `messages` | 聊天记录（含人工），`is_read` 未读标记 |
| 工单 | MySQL | `tickets` / `ticket_logs` | 工单 + 操作历史（状态：0 待处理/1 接管中/2 已取消/3 已关闭） |
| 审计 | MySQL | `audit_logs` | 管理端操作审计（login/变更/接管…） |
| 消息归档 | MySQL | `messages_archive` | 超保留期迁移（默认 90 天） |
| 订单 | MySQL | `orders` | Agent 订单查询工具演示数据 |
| 会话状态 | PostgreSQL | `checkpoints` 系列 | LangGraph checkpoint（自动建表） |
| 会话元数据 | PostgreSQL | `session_meta` | 活跃时间/消息数，供回收与配额 |
| Prompt | PostgreSQL | `prompts`（PK=tenant_id+key）/ `prompt_versions` | 版本快照/回滚 |
| 知识库文档 | PostgreSQL | `kb_documents` | 元数据 + file_url（原文件在共享卷） |
| 平台设置 | PostgreSQL | `platform_settings` | key-value（如 kb_max_file_mb） |
| Token 用量 | PostgreSQL | `token_usage` | 计费与用量报表 |
| 知识库向量 | Qdrant | `kb_{tenant_id}` | 向量检索（Cosine） |
| 缓存/锁/队列 | Redis | `cs:login:fail:*`、`cs:tok:bl:*`、`cs:model:cache:invalidate`、`cs:kb:index:queue`、SETNX 锁 | 运行时基础设施 |

**原则**：业务数据（事务/报表/关联查询）→ MySQL；Agent 运行时状态与 AI 配置 → PostgreSQL；向量 → Qdrant；跨实例协同 → Redis。新表先想归属再动手。
**DDL 唯一来源**：`deploy/init/mysql/init.sql` 与 `deploy/init/postgres/init.sql`（compose 首次启动自动执行；Go 侧 AutoMigrate/Agent 侧 verify 幂等兼容）。

## 7. 核心请求链路

### 7.1 用户聊天（流式）

```
POST /api/user/chat（或 WS /ws/chat 转发）
  → Go 鉴权（UserAuth：token + user_id 归属租户）→ 落 messages（user 消息）
  → pkg/agent/client.go 调 http://agent:8000/agent/chat/stream（SSE，X-Trace-Id 透传）
  → Agent：check_concurrent_sessions 配额校验 → get_tenant_agent（配置缓存+签名兜底）
  → LangGraph astream(stream_mode="messages")：RAG 检索 Qdrant + 工具调用 + Prompt
  → SSE 逐 token：chunk / end / interrupt / error
  → Go 逐 chunk 经 WS 推给前端；结束后落 messages（ai 消息）+ 用量记录（token_usage）
```

### 7.2 转人工（人工接管）

```
用户触发 transfer_to_human 工具 → LangGraph interrupt（挂起）
  → Agent 返回 is_interrupt=true → Go 创建工单（tickets，status=0 待处理）
  → 管理端 /ws/admin 收到 new_ticket 通知 → 客服接管（POST /api/admin/tickets/:id/takeover）
  → 客服回复经 WS 直推用户；AI 在待处理工单存在时不再重复触发转人工
  → 用户侧 resume（confirmed/wait_time/ticket_id）→ Agent Command(resume) 恢复对话
```

### 7.3 模型配置变更（缓存失效广播）

```
管理端保存模型配置（平台/代配/自配任一）
  → Go 落库 tenants（AES 加密 Key）→ cache.Publish("cs:model:cache:invalidate", {tenant_id, scope, ts})
  → 所有 Agent 实例订阅消费 → clear_tenant_caches(scope 粒度) → 重建 Agent/检索器
  → 兜底：Agent 每次构建前懒查 config_version 签名（10s TTL），广播丢失 ≤10s 最终一致
```

## 8. 开发规范

### 提交前必做

1. **先 commit 再动代码**：修改前确保工作区干净并提交当前状态（历史教训：曾因未提交导致改动无法还原）。
2. **CRLF 行尾**：仓库 `.gitattributes` 已配 `*.sh/*.go/*.py/*.md eol=lf`；从 Windows 检出若出现 `\r` 报错，执行 `sed -i 's/\r$//' <file>`；含中文文件禁用 PowerShell `Set-Content` 写入。
3. **WSL 执行脚本**：复杂命令写 `.sh` 后 `tr -d '\r' < x.sh > /tmp/x.sh && bash /tmp/x.sh`（PowerShell 直写含 `$` 的命令会报错）。
4. **修改服务端代码后**：`docker compose up -d --build go`（或 agent）；前端/nginx 改动即时生效（ro 挂载）；nginx.conf 改动后 `docker exec cs_nginx nginx -s reload`。
5. **数据库结构变更**：只改 `deploy/init/mysql/init.sql` / `deploy/init/postgres/init.sql`（DDL 唯一来源），不要靠代码自动建表漂移。
6. **验证通过才提交**：见下节命令。

### 验证命令

```bash
# 健康自检（6 步 14 项断言：容器/登录/核心接口）
bash scripts/run_healthcheck.sh

# P0 回归：Go 单测（16 项）+ Agent 单测（5 项）
bash scripts/run_p0_tests.sh        # 或 scripts/run_go_tests.sh

# Agent 单测（容器内）
docker cp python_agent/test_agent_unit.py cs_agent:/app/ && docker exec cs_agent python3 /app/test_agent_unit.py

# 语法检查
bash scripts/check_py_syntax.sh

# 关键接口回归（登录/防爆破/租户列表/404）
bash scripts/verify_p2_1.sh

# E2E（WS 聊天+人工接管）与功能测试（Prompt/知识库/会话清理）
python scripts/e2e_test.py && python scripts/feature_test.py

# 管理后台重新构建（改 admin-app 后）
# 方式一：容器内自动编译（推荐，无需宿主机 Node，nginx.Dockerfile 多阶段构建）
docker compose up -d --build nginx
# 方式二：宿主机本地构建（需 WSL + Windows Node，见 scripts/build_admin_app.sh）
bash scripts/build_admin_app.sh
```

### 常见坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 接口返回 429 | 登录防爆破（同一 IP+app_key 连续失败 5 次锁 10 分钟，Redis 存储） | 等待解锁或 `docker restart cs_go`（Redis 计数不清除，需清 `cs:login:fail:*`） |
| Go/Agent 启动失败 | Redis 不可用（强制依赖，fail-fast） | `docker compose ps cs_redis` 确认健康 |
| SQL 导入中文乱码 | 文件/连接非 utf8mb4 | `SET NAMES utf8mb4;` 后 source |
| agent 容器反复重启 | Python 语法/import 错误 | `docker logs cs_agent` 定位；`docker compose run --rm --no-deps agent python main.py` 前台复现 |
| Go 容器 502 | nginx 变量缓存旧 IP | 已用变量解析 DNS；容器重建后无需处理 |
| 健康自检失败 | 脚本 CRLF | `sed -i 's/\r$//' scripts/*.sh` |
| 切模型不生效 | Agent 缓存未失效 | 确认 Redis 广播订阅存活（`docker logs cs_agent` 看清除记录）；签名兜底 ≤10s |
| 知识库检索不到 | 文档未完成索引 / 换过 Embedding 模型 | 文档状态需为「已索引」；换模型后必须重新索引 |
