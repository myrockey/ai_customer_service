## 1.3 Redis 运维说明（强制依赖）

> **Redis 是本系统强制依赖的基础设施**（登录限流 / Token 黑名单 / 模型配置缓存失效广播 / 定时任务锁），
> 与 MySQL / PostgreSQL / Qdrant 同级。服务不可用时：启动 fail-fast（部署即失败）、运行期 fail-closed（登录被拒，不静默降级）。

### 1.3.1 健康检查

```bash
# 容器状态（cs_redis 应为 healthy）
docker compose ps

# 连通性
docker exec cs_redis redis-cli ping        # 期望 PONG

# 查看内存与持久化
docker exec cs_redis redis-cli info memory | grep -E 'used_memory_human|maxmemory'
docker exec cs_redis redis-cli info persistence | grep aof
```

### 1.3.2 数据说明

| Key 前缀 | 用途 | 丢失影响 |
|---|---|---|
| `cs:login:fail:*` | 登录失败计数（限流） | 可重建：用户重新登录即恢复计数 |
| `cs:tok:bl:*` | Token 黑名单 | 可重建：黑名单失效=已登出 token 短期可复用，安全性影响小，建议保留 AOF |
| `cs:model:cache:invalidate` | 缓存失效广播（pub/sub，无持久化） | 无影响：广播丢失由「配置签名对比」≤10s 自愈 |
| `cs:lock:session_cleanup` | 定时任务锁 | 无影响：锁过期自动释放 |

数据持久化在命名卷 `cs_redis_data_prod`（AOF），删除容器不丢数据；`docker compose down -v` 才会清空。

### 1.3.3 高可用建议

单实例 Redis 存在**单点故障**（宕机 = 登录不可用）。生产环境建议二选一：

1. **云 Redis（推荐）**：阿里云/腾讯云 Redis 高可用版，自带主从 + 哨兵 + 监控告警；将 `REDIS_ADDR` / `REDIS_URL` 指向云实例即可。
2. **自建主从 + Sentinel**：compose 起 1 主 1 从 + 3 哨兵（`quorum=2`），客户端改为 FailoverClient 自动跟随切换；单机只能演练切换，跨机 HA 需多主机。

### 1.3.4 监控（可选）

Prometheus 采集 Redis 指标需部署 `redis_exporter`（未随包内置）：

```yaml
# docker-compose 追加（observability profile）
redis-exporter:
  image: oliver006/redis_exporter:v0.63.0
  profiles: ["observability"]
  environment:
    REDIS_ADDR: redis://redis:6379
  ports:
    - "9121:9121"
```

加入后可在 Prometheus 配置追加抓取目标，Grafana 使用官方 Redis 仪表盘（ID: 763）。

## 2. Grafana 使用指南

### 2.1 登录与初始配置

1. 访问 http://localhost:3000
2. 输入默认账号：admin / admin123
3. 首次登录建议修改密码（左下角 → Preferences → Change Password）

| Prometheus | 默认 | 指标数据，地址：http://prometheus:9090 |

### 2.3 预置仪表盘

系统已预置"智能客服系统 - 总览"仪表盘，包含以下面板：

| 面板 | 类型 | 说明 |
|------|------|------|
| WebSocket 连接数 | Stat | 当前活跃 WebSocket 连接数 |
| HTTP 请求 QPS | Stat | 每秒请求数 |
| HTTP P95 延迟 | Stat | 95 分位请求延迟 |
| HTTP 5xx 错误率 | Stat | 5xx 错误占比 |
| HTTP 请求数趋势 | Time Series | 按状态码的请求数趋势 |
| HTTP 请求延迟分布 | Time Series | P50/P90/P95/P99 延迟趋势 |

**访问仪表盘**：
- 左侧菜单 → Dashboards → 智能客服系统 → 智能客服系统 - 总览

**仪表盘操作**：
- 时间范围选择：右上角时间选择器（最近 5 分钟/15 分钟/1 小时/6 小时/24 小时/7 天）

- 面板查看：点击面板标题 → View，查看大图
- 面板编辑：点击面板标题 → Edit，编辑查询和样式

2. 点击 Add visualization

### 2.5 常用 PromQL 查询

**HTTP 请求 QPS**：
```promql
sum(rate(cs_http_requests_total[1m]))
```

**按状态码的请求数**：
```promql
sum by (status) (rate(cs_http_requests_total[5m]))
```

**5xx 错误率**：
```promql
sum(rate(cs_http_requests_total{status=~"5.."}[5m]))
/
sum(rate(cs_http_requests_total[5m]))
```

**P95 请求延迟**：
```promql
histogram_quantile(0.95, sum(rate(cs_http_request_duration_seconds_bucket[5m])) by (le))
```

**P99 请求延迟**：
```promql
histogram_quantile(0.99, sum(rate(cs_http_request_duration_seconds_bucket[5m])) by (le))
```

**WebSocket 连接数**：
```promql
cs_websocket_connections
```

**Agent 调用次数**：
```promql
sum(rate(cs_agent_calls_total[5m]))
```

**Agent 调用失败率**：
```promql
sum(rate(cs_agent_calls_total{status="error"}[5m]))
/
sum(rate(cs_agent_calls_total[5m]))
```

**请求量排名（按 path）**：
```promql
topk(10, sum by (path) (rate(cs_http_requests_total[1h])))
```

## 3. Prometheus 使用指南

### 3.1 访问与界面

访问 http://localhost:9090，主要功能：

| 功能 | 路径 | 说明 |
|------|------|------|
| 指标查询 | /graph | PromQL 查询、图表展示 |
| 目标状态 | /targets | 查看所有抓取目标的健康状态 |
| 告警规则 | /alerts | 查看告警规则和触发状态 |
| 配置信息 | /config | 查看 Prometheus 配置 |
| 运行状态 | /status | 查看运行时信息 |

### 3.2 目标状态

访问 http://localhost:9090/targets，查看抓取目标：

| 目标 | 地址 | 说明 |
|------|------|------|
| go-service | go:8080/metrics | Go 网关服务指标 |
| prometheus | localhost:9090/metrics | Prometheus 自身指标 |

**状态说明**：
- UP：目标健康，正常抓取
- DOWN：目标不可达，检查服务是否运行、网络是否通
- 最近抓取时间：上次成功抓取的时间
- 抓取耗时：上次抓取的耗时

### 3.3 指标查询

访问 http://localhost:9090/graph，输入 PromQL 查询：

**查询示例**：
```promql
# 查看所有指标名
cs_http_requests_total

# 按标签筛选
cs_http_requests_total{status="200", method="GET"}

# 正则匹配
cs_http_requests_total{status=~"5.."}

# 速率计算
rate(cs_http_requests_total[5m])

# 聚合
sum by (status) (rate(cs_http_requests_total[5m]))

# 分位数
histogram_quantile(0.95, sum(rate(cs_http_request_duration_seconds_bucket[5m])) by (le))
```

**查询结果展示**：
- Table：表格形式展示当前值
- Graph：折线图展示历史趋势
- 可调整时间范围、分辨率

### 3.4 告警规则

访问 http://localhost:9090/alerts，查看告警规则：

- 规则名称、查询条件、持续时间
- 当前状态：Inactive（未触发）、Pending（等待持续时间）、Firing（已触发）
- 触发时间、标签、注释

### 3.5 配置文件

Prometheus 配置文件路径：`deploy/observability/prometheus.yml`

**主要配置项**：
```yaml
global:
  scrape_interval: 15s          # 抓取间隔
  evaluation_interval: 15s      # 告警评估间隔

rule_files:
  - /etc/prometheus/rules/*.yml  # 告警规则文件

scrape_configs:
  - job_name: 'go-service'       # 任务名
    metrics_path: '/metrics'      # 指标路径
    static_configs:
      - targets: ['go:8080']     # 目标地址
```

**修改配置后重载**：
```bash
# 方式1：重启容器
docker compose restart prometheus

# 方式2：热重载（需要开启 --web.enable-lifecycle）
curl -X POST http://localhost:9090/-/reload
```

## 4. Loki 使用指南

### 4.1 日志架构

```
应用 stdout → Docker 日志 → Promtail → Loki → Grafana 查询
```

**Promtail 配置**：`deploy/observability/promtail-config.yaml`
- Docker 服务发现，自动发现所有容器
- 只收集 `cs_` 前缀的容器日志
- 解析 JSON 格式日志，提取 level、trace_id、tenant_id 等标签
- 推送到 Loki（http://loki:3100/loki/api/v1/push）

### 4.2 通过 Grafana 查询日志

1. 访问 Grafana → 左侧菜单 → Explore
2. 左上角选择数据源：Loki
3. 输入 LogQL 查询语句
4. 点击 Run query 执行查询

### 4.3 常用 LogQL 查询

**查询 Go 服务所有日志**：
```logql
{container="cs_go"}
```

**查询 Agent 服务所有日志**：
```logql
{container="cs_agent"}
```

**查询错误日志**：
```logql
{container="cs_go"} |= "error"
```

**按 trace_id 查询**：
```logql
{container="cs_go"} |="trace_id" | json | trace_id="05d8af59-836c-4d14-bbb9-aee10ffe97e3"
```

**按租户查询**：
```logql
{container="cs_go"} | json | tenant_id="t_demo"
```

**按日志级别查询**：
```logql
{container="cs_go"} | json | level="error"
```

**统计错误日志数量**：
```logql
count_over_time({container="cs_go"} | json | level="error" [5m])
```

**查询 HTTP 请求日志**：
```logql
{container="cs_go"} |="HTTP请求完成" | json
```

**查询慢请求（>1秒）**：
```logql
{container="cs_go"} |="HTTP请求完成" | json | duration > 1000
```

**实时日志流**：
```logql
{container="cs_go"}
```
（在 Grafana Explore 中点击 Live 按钮，实时查看日志流）

### 4.4 Loki API 查询

```bash
# 查询日志（范围查询）
curl -G 'http://localhost:3100/loki/api/v1/query_range' \
  --data-urlencode 'query={container="cs_go"}' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'start=1693987200' \
  --data-urlencode 'end=1694073600'

# 即时查询
curl -G 'http://localhost:3100/loki/api/v1/query' \
  --data-urlencode 'query=count_over_time({container="cs_go"}[1h])'

# 查询标签
curl 'http://localhost:3100/loki/api/v1/labels'

# 查询标签值
curl 'http://localhost:3100/loki/api/v1/label/container/values'
```

### 4.5 日志保留策略

- 默认保留：7 天
- 配置文件：`deploy/observability/loki-config.yaml`
- 修改 `retention_period` 可调整保留时间
- 存储位置：Docker Volume `cs_loki_data`

### 5.3 Trace 详情

点击某个 trace，查看详情：

**Trace 概览**：
- Trace ID：唯一标识
- 总耗时：从请求开始到结束的总时间
- Span 数量：调用链中的 span 总数
- 服务数量：涉及的服务数

**Span 列表**：
- 每个 span 显示：服务名、操作名、开始时间、耗时、状态
- 时间轴展示各 span 的并行/串行关系
- 点击 span 查看详情

**Span 详情**：
- Tags：标签信息（HTTP method、url、status_code、client_ip 等）
- Process：服务进程信息
- Logs：span 内的日志事件
- References：父子 span 关系

### 5.4 按 trace_id 查询

如果已知 trace_id（从日志、响应头 X-Trace-Id 获取）：

1. 访问 http://localhost:16686/trace/{trace_id}
2. 直接查看该 trace 的完整调用链

示例：http://localhost:16686/trace/05d8af59836c4d14bbb9aee10ffe97e3

### 5.5 系统架构图

访问 http://localhost:16686/architecture，查看：
- 服务依赖关系图
- 各服务的调用频率、平均延迟
- 点击节点查看该服务的详细信息

### 5.6 采样策略

当前配置：
- 默认采样率：10%（`OTEL_TRACES_SAMPLER_ARG=0.1`）
- 采样器：parentbased_traceidratio（有父 span 时继承父采样决策，否则按比例采样）
- 错误请求：建议配置 100% 采样（可通过 tail-based sampling 实现）

**调整采样率**：
修改 `docker-compose.yaml` 中 go 服务的环境变量：
```yaml
environment:
  OTEL_TRACES_SAMPLER_ARG: "0.5"  # 改为 50% 采样
```

**生产环境建议**：
- 正常流量：10-20% 采样，降低存储成本
- 错误请求：100% 采样，便于问题排查
- 慢请求：100% 采样，便于性能分析
- 可通过 Jaeger 的 tail-based sampling 实现

### 5.7 存储配置

当前使用内存存储：
- 最多保留 10000 条 trace（`MEMORY_MAX_TRACES=10000`）
- 重启后数据丢失
- 适合开发、测试环境

**生产环境建议**：
- 使用 Elasticsearch、Cassandra 或 Badger 持久化存储
- 配置保留策略（如保留 7 天）
- 配置资源限制（内存、CPU）

## 6. 告警处理流程

### 6.1 告警级别

| 级别 | 颜色 | 响应时间 | 说明 |
|------|------|---------|------|
| Critical | 红色 | 立即（5 分钟内） | 系统不可用、数据丢失、安全问题 |
| Warning | 黄色 | 1 小时内 | 性能下降、错误率升高、资源接近阈值 |
| Info | 蓝色 | 24 小时内 | 一般性通知、状态变化 |

### 6.2 常见告警处理

**HighHTTPErrorRate（5xx 错误率 > 5%）**：
1. 查看 Grafana 仪表盘，确认错误率趋势
2. 查询 Loki 日志，筛选错误日志：`{container="cs_go"} | json | level="error"`
3. 查看 Jaeger，追踪错误请求的完整调用链
4. 检查 Agent 服务是否正常、模型 API 是否可用
5. 检查数据库连接池是否耗尽
6. 修复问题后，观察错误率是否下降

**HighHTTPRequestLatency（P95 延迟 > 3 秒）**：
1. 查看延迟分布，确认是整体变慢还是特定接口
2. 查询慢请求日志：`{container="cs_go"} |="HTTP请求完成" | json | duration > 3000`
3. 查看 Jaeger，分析慢请求的调用链，定位耗时环节
4. 检查 Agent 模型 API 响应速度
5. 检查数据库慢查询
6. 检查知识库检索是否命中缓存

**HighWebSocketConnections（连接数 > 1000）**：
1. 确认是否为正常业务增长
2. 检查是否有异常连接（单 IP 大量连接）
3. 查看 Go 服务内存、CPU 使用情况
4. 考虑水平扩展 Go 服务实例

**ServiceDown（服务宕机）**：
1. 立即检查容器状态：`docker compose ps`
2. 查看服务日志：`docker compose logs go --tail 100`
3. 尝试重启服务：`docker compose restart go`
4. 如果重启失败，检查依赖服务（MySQL、Agent）是否正常
5. 检查端口是否被占用、资源是否充足

### 6.3 告警通知配置

**邮件通知**：
1. Grafana → Alerting → Contact points → New contact point
2. 类型选择 Email
3. 填写收件人邮箱、SMTP 配置

**Webhook 通知**：
1. 类型选择 Webhook
2. 填写 Webhook URL
3. 配置自定义 Headers（如认证 Token）
4. 测试并保存

**钉钉/企业微信通知**：

2. 在 Grafana 中配置 Webhook 通知
3. 配置消息模板（适配钉钉/企业微信格式）

| Go 服务内存 | < 70% | > 80% | > 90% |

### 7.2 性能分析流程

1. **发现问题**：Grafana 告警或仪表盘发现异常
2. **定位范围**：确定是整体问题还是特定接口/租户
3. **日志分析**：Loki 查询相关日志，查看错误信息
4. **链路追踪**：Jaeger 查看慢请求/错误请求的调用链
5. **资源监控**：查看 CPU、内存、磁盘、网络使用情况
6. **数据库分析**：查看慢查询、连接数、锁等待
7. **修复验证**：修复后观察指标是否恢复正常

- 调整数据库连接池大小（config.yaml 中配置）

- 静态资源缓存
- 水平扩展多实例

- 增加 Worker 数量
- 调整模型 API 超时时间
- 知识库检索缓存（已实现，TTL 5 分钟）
- 异步处理非实时任务

**数据库优化**：
- 添加合适的索引（已添加 4 个复合索引）
- 定期清理过期数据
- 慢查询优化
- 读写分离（高并发场景）

**模型 API 优化**：
- 使用更快的模型
- 调整 max_tokens 限制
- 启用流式输出（已实现）
- 缓存高频问题的回答

## 9. 故障排查手册

### 9.1 服务无法启动

**排查步骤**：
1. 查看容器状态：`docker compose ps`
2. 查看服务日志：`docker compose logs <service> --tail 100`
3. 检查依赖服务是否正常
4. 检查配置文件是否正确
5. 检查端口是否被占用：`netstat -tlnp | grep <port>`
6. 检查资源是否充足：`free -h`、`df -h`

**常见原因**：
- 配置文件错误（API Key、数据库连接串）
- 依赖服务未启动（MySQL、Agent）
- 端口被占用
- 磁盘空间不足
- 内存不足导致 OOM

### 9.2 AI 回复很慢或无响应

**排查步骤**：
1. 查看 Grafana，确认 P95 延迟是否升高
2. 查看 Loki 日志，筛选慢请求
3. 查看 Jaeger，分析调用链，定位耗时环节
4. 检查 Agent 服务状态和日志
5. 测试模型 API 直接调用速度
6. 检查知识库检索是否命中缓存

**常见原因**：
- 模型 API 响应慢（网络、限流、模型负载）
- 知识库检索慢（Qdrant 负载、向量维度高）
- Agent Worker 数不足
- 数据库慢查询
- 网络延迟

### 9.3 WebSocket 连接频繁断开

**排查步骤**：
1. 查看 Go 服务日志，筛选 WebSocket 相关错误
2. 检查频率限制是否触发
3. 检查网络稳定性（客户端、服务端）
4. 检查 Nginx 代理配置（超时、缓冲区）
5. 检查 Go 服务内存、CPU 使用情况

**常见原因**：
- 频率限制触发（单 IP/单用户连接数、消息频率）
- Nginx 代理超时（默认 60 秒无消息断开）
- 客户端网络不稳定
- 服务端资源不足

### 9.4 知识库检索不到内容

**排查步骤**：
1. 确认文档索引状态为"已完成"
2. 检查 Qdrant 集合是否存在：`curl http://localhost:6333/collections`
3. 检查集合中向量数量
4. 测试 Embedding 模型是否正常
5. 检查租户 ID 是否匹配
6. 查看 Agent 日志，筛选检索相关日志

**常见原因**：
- 文档索引失败（查看错误信息）
- Embedding 模型不匹配（生成和查询使用不同模型）
- 租户 ID 不匹配（查询错误的集合）
- 问题描述与文档内容差异大
- Qdrant 服务异常
