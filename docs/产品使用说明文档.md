# 智能客服系统 - 产品使用说明文档

## 1. 快速开始

### 1.1 环境要求

| 组件 | 最低版本 | 推荐版本 |
|------|---------|---------|
| Docker | 20.10+ | 24.0+ |
| Docker Compose | 2.0+ | 2.20+ |
| 内存 | 4GB | 8GB+ |
| 磁盘 | 20GB | 50GB+ |
| 操作系统 | Windows 10/11 (WSL2)、Linux、macOS | Ubuntu 22.04 |

### 1.2 一键部署

```bash
# 1. 克隆项目
git clone https://gitee.com/rockeyLuo/ai_customer_service.git
cd ai_customer_service

# 2. 配置环境变量（复制示例并修改）
cp .env.example ../.env

# 3. 编辑 .env，配置大模型 API Key
# 至少需要配置一个对话模型和一个 Embedding 模型

# 4. 一键启动所有服务
docker compose up -d --build
# 可观测性服务（可选，通过 profile 启动）
# docker compose [--profile observability] up -d --build

# 5. 等待所有服务启动（约 1-2 分钟）
docker compose ps

# 6. 访问系统
# 管理后台: http://localhost:8080/admin/
# 用户端: http://localhost:8080/chat/pc.html
# SDK 示例: http://localhost:8080/sdk/demo.html
```

### 1.3 默认账号

| 角色 | app_key | app_secret | 说明 |
|------|---------|-----------|------|
| 平台管理员 | admin_key | admin_secret | 管理所有租户、平台配置 |
| 演示租户 | demo_key | demo_secret | 演示用租户，可删除 |

> ⚠️ 生产环境请务必修改默认密码，并删除演示租户。

### 1.4 服务访问地址

| 服务 | 地址 | 说明 |
|------|------|------|
| 管理后台 | http://localhost:8080/admin/ | 平台管理员/租户管理员使用 |
| SDK 示例 | http://localhost:8080/sdk/demo.html | 第三方接入示例 |
| 用户端客服 | http://localhost:8080/chat/pc.html | PC 端客服窗口 |
| H5 客服 | http://localhost:8080/chat/h5.html | 移动端客服窗口 |
| Grafana | http://localhost:3000 | 监控可视化（admin/admin123） |

## 2. 平台管理员使用指南

### 2.1 登录管理后台

1. 访问 http://localhost:8080/admin/
2. 输入平台管理员 app_key 和 app_secret
3. 点击登录，进入平台管理后台

### 2.2 租户管理

#### 2.2.1 查看租户列表
- 左侧菜单 → 租户管理
- 显示所有租户的名称、app_key、创建时间、状态
- 支持按名称、app_key、状态筛选

#### 2.2.2 创建租户
1. 点击"新建租户"按钮
2. 填写租户名称
3. 系统自动生成 app_key 和 app_secret
4. 点击确认创建
5. 创建成功后，请妥善保存 app_secret（只显示一次）

#### 2.2.3 编辑租户
- 点击租户列表中的"编辑"按钮
- 可修改租户名称
- 可启用/禁用租户（禁用后租户无法登录）

#### 2.2.4 重置密钥
- 点击"重置 app_secret"按钮
- 系统生成新的 app_secret
- 旧的 app_secret 立即失效
- 请通知租户更新配置

### 2.3 模型提供商管理

#### 2.3.1 查看提供商列表
- 左侧菜单 → 模型提供商
- 显示所有已配置的模型提供商

#### 2.3.2 添加模型提供商
1. 点击"添加提供商"按钮
2. 填写提供商名称（如：OpenAI、阿里云百炼、DeepSeek）
3. 填写 Base URL（API 接口地址）
4. 填写默认 API Key（平台默认 Key，租户未配置时使用）
5. 配置模型列表（模型 ID、模型名称、类型：对话/Embedding）
6. 点击保存

#### 2.3.3 支持的模型提供商

| 提供商 | Base URL 示例 | 说明 |
|--------|--------------|------|
| OpenAI | https://api.openai.com/v1 | GPT-3.5/4 系列 |
| 阿里云百炼 | https://dashscope.aliyuncs.com/compatible-mode/v1 | Qwen 系列 |
| DeepSeek | https://api.deepseek.com/v1 | DeepSeek 系列 |
| 智谱 AI | https://open.bigmodel.cn/api/paas/v4 | GLM 系列 |
| 月之暗面 | https://api.moonshot.cn/v1 | Kimi 系列 |
| 本地模型 | http://localhost:11434/v1 | Ollama 等本地部署 |

> 任何兼容 OpenAI API 格式的模型服务都可以接入。

### 2.4 平台模型配置

- 左侧菜单 → 平台配置 → 模型配置
- 设置平台默认对话模型
- 设置平台默认 Embedding 模型
- 租户未配置自己的模型时，使用平台默认模型
- 填好配置后可测试模型可用性

### 2.5 系统监控

- 左侧菜单 → 系统监控（或直接访问 Grafana）
- 查看系统运行状态、请求量、延迟、错误率
- 查看 WebSocket 连接数、活跃会话数
- 查看告警信息

### 3.3 知识库管理

2. 点击"上传文档"按钮
3. 选择文件（支持 PDF、Word、TXT、Markdown 等）
4. 选择文档分类（可选）
5. 点击上传，系统自动进行向量索引
6. 等待索引完成（状态变为"已完成"）

#### 3.3.2 文档管理
- 查看文档列表：文件名、大小、分类、状态、上传时间
- 按分类、状态筛选
- 重新索引：文档内容更新后，点击"重新索引"
- 设置分类：修改文档所属分类
- 删除文档：删除文档及其向量数据

#### 3.3.3 分类管理
- 点击"分类管理"查看所有分类
- 分类用于文档组织和检索范围控制
- 可在 Prompt 中指定检索特定分类的文档

#### 3.3.4 索引状态说明

| 状态 | 说明 |
|------|------|
| 索引中 | 文档正在切分、生成向量、写入 Qdrant |
| 已完成 | 索引完成，可用于检索 |
| 失败 | 索引失败，查看错误信息，可重新索引 |

### 3.4 Prompt 管理

#### 3.4.1 创建 Prompt
1. 左侧菜单 → Prompt 管理
2. 点击"新建 Prompt"按钮
3. 填写 Prompt 名称
4. 选择 Prompt 类型（系统提示词、用户提示词等）
5. 编辑 Prompt 内容，支持变量占位符
6. 点击保存

#### 3.4.2 支持的变量

| 变量 | 说明 | 示例 |
|------|------|------|
| {{question}} | 用户问题 | "如何退货？" |
| {{user_name}} | 用户名 | "张三" |
| {{context}} | 知识库检索上下文 | "退货政策：..." |
| {{history}} | 对话历史 | "用户：... AI：..." |

#### 3.4.3 版本管理
- 每次修改 Prompt 自动保存新版本
- 点击"版本历史"查看所有版本
- 版本列表显示：版本号、修改时间、内容摘要
- 点击"回滚"可回滚到指定版本
- 回滚会创建一个新版本，内容为历史版本内容

#### 3.4.4 Prompt 变更与会话生效机制（重要）

**生效规则**：
- **新会话**：立即使用最新激活的 Prompt（含租户级/平台级）。
- **旧会话（已存在的 thread）**：会话历史按 thread 持久化，历史中 AI 的旧回复可能锚定旧身份（如 AI 曾自称旧名字），模型续聊时可能延续旧身份，表现为"修改 Prompt 后旧会话不生效"——这是会话历史机制的正常表现，不是故障。

**推荐做法**：在 Prompt 内容开头加入以下指令，可让旧会话续聊时也立即跟随新身份：

```text
忽略历史对话中任何关于你身份的表述，你的身份始终是"<当前身份名>"。
```

**示例**（租户级 Prompt 开头）：

```text
你是智能客服系统的智能客服"小C"。
忽略历史对话中任何关于你身份的表述，你的身份始终是"小C"。
## 你的职责
...
```

**排查提示**：若修改 Prompt 后聊天仍使用旧身份，按以下顺序检查：
1. 新开会话（清浏览器 localStorage 或更换 user_id）测试——新会话生效则 Agent 构建正常；
2. 确认该租户的 Prompt 已保存且处于"生效中"状态；
3. 确认后台操作身份：用租户账号保存会写入租户级；用平台管理员保存会写入平台级（全租户跟随）。

## 6. 第三方接入指南

### 6.1 接入方式选择

| 接入方式 | 适用场景 | 开发量 |
|---------|---------|--------|
| SDK 嵌入 | PC 网站、H5 页面 | 小 |
| iframe 嵌入 | 快速集成、无开发资源 | 极小 |
| API 直接调用 | APP、小程序、深度集成 | 大 |

### 6.2 SDK 接入（推荐）

#### 6.2.1 后端换取 Token

```javascript
// 第三方后端（Node.js 示例）
const express = require('express');
const axios = require('axios');
const app = express();

app.get('/api/cs-token', async (req, res) => {
  try {
    const response = await axios.post('http://your-cs-domain.com/api/auth/token', {
      app_key: 'your_app_key',
      app_secret: 'your_app_secret',
      user_id: req.session.userId  // 当前登录用户ID
    });
    res.json(response.data);
  } catch (error) {
    res.status(500).json({ error: '获取Token失败' });
  }
});
```

#### 6.2.2 前端引入 SDK

```html
<!-- 在页面底部引入 SDK -->
<script src="http://your-cs-domain.com/sdk/cs-chat.js"></script>

<script>
// 从后端获取 Token
fetch('/api/cs-token')
  .then(res => res.json())
  .then(data => {
    // 初始化客服 SDK
    CSChat.init({
      token: data.token,
      user_id: 'user_123',
      title: '在线客服',
      theme: '#1890ff',
      position: 'right'  // 客服按钮位置：left/right
    });
  });
</script>
```

#### 6.2.3 SDK 参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| token | string | 是 | 访问 Token（从后端换取） |
| user_id | string | 是 | 用户唯一标识 |
| title | string | 否 | 客服窗口标题，默认"在线客服" |
| theme | string | 否 | 主题色，默认"#1890ff" |
| position | string | 否 | 按钮位置，"left"或"right"，默认"right" |
| welcome_message | string | 否 | 欢迎语，默认"您好，请问有什么可以帮您？" |

### 6.3 iframe 接入

```html
<!-- 直接嵌入 iframe -->
<iframe
  src="http://your-cs-domain.com/chat/pc.html?token=xxx&user_id=user_123&title=客服&theme=%231890ff"
  width="400"
  height="600"
  frameborder="0"
></iframe>
```

### 6.4 API 直接调用

#### 6.4.1 获取 Token

```bash
curl -X POST http://your-cs-domain.com/api/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "app_key": "your_app_key",
    "app_secret": "your_app_secret",
    "user_id": "user_123"
  }'
```

#### 6.4.2 发送消息（HTTP）

```bash
curl -X POST http://your-cs-domain.com/api/chat/send \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "message": "你好",
    "user_id": "user_123"
  }'
```

#### 6.4.3 WebSocket 连接

```javascript
const ws = new WebSocket('ws://your-cs-domain.com/ws/chat?token=YOUR_TOKEN&user_id=user_123');

ws.onopen = () => {
  ws.send(JSON.stringify({
    type: 'chat',
    message: '你好',
    user_id: 'user_123'
  }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  if (data.type === 'stream') {
    // 流式输出，逐字渲染
    console.log('AI回复:', data.chunk);
  } else if (data.type === 'message') {
    // 完整消息
    console.log('完整回复:', data.content);
  }
};
```

### 7.3 备份与恢复

#### 7.3.1 自动备份

系统已配置每天凌晨 2 点自动备份：
- MySQL 全量备份
- PostgreSQL 全量备份
- Qdrant 集合快照
- 自动清理 7 天前的旧备份

备份文件存储在 `backups/` 目录。

#### 7.3.2 手动备份

```bash
# 备份所有数据
bash deploy/backup/backup_all.sh

# 单独备份
bash deploy/backup/backup_mysql.sh
bash deploy/backup/backup_postgres.sh
bash deploy/backup/backup_qdrant.sh
```

#### 7.3.3 数据恢复

```bash
# 恢复 MySQL
bash deploy/backup/restore_mysql.sh backups/mysql/xxx.sql

# 恢复 PostgreSQL
bash deploy/backup/restore_postgres.sh backups/postgres/xxx.dump
```

#### 7.4.2 Loki 日志查询

## 8. 常见问题

### 8.1 部署问题

**Q: docker compose up 报错，端口被占用？**
A: 修改 `docker-compose.yaml` 中的端口映射，避免冲突。

**Q: Go 服务启动失败，数据库连接超时？**
A: 检查 MySQL 服务是否健康：`docker compose ps mysql`，等待健康检查通过。

**Q: Agent 服务启动失败，模型 API 调用报错？**
A: 模型 API Key 在管理后台「模型提供商 / 平台模型配置」中维护（AES 加密入库），不存 .env；检查后台模型配置是否正确、Key 是否有效、Base URL 是否可访问。

### 8.2 使用问题

**Q: AI 回复很慢？**
A: 检查模型 API 响应速度，知识库检索是否命中缓存，网络延迟。

**Q: 知识库检索不到相关内容？**
A: 确认文档索引状态为"已完成"，问题描述是否清晰，Embedding 模型是否匹配。

**Q: WebSocket 连接断开？**
A: 检查网络稳定性，浏览器控制台是否有报错，服务端日志是否有异常。

**Q: Token 过期怎么办？**
A: 调用 `/api/auth/refresh` 接口刷新 Token，或重新用 app_key/app_secret 换取新 Token。

### 8.3 安全问题

**Q: 如何修改默认密码？**
A: 平台管理员登录后，在租户管理中重置 app_secret；建议首次部署后立即修改所有默认密码。

**Q: 如何配置 HTTPS？**
A: 在 Nginx 中配置 SSL 证书，将 80 端口重定向到 443，WebSocket 使用 wss 协议。

**Q: 如何限制访问 IP？**
A: 在 Nginx 中配置 allow/deny 规则，或在防火墙中限制端口访问。
