## 2. 认证鉴权模块

### 2.1 功能概述
基于 Token 的无状态认证体系，支持多租户隔离、内部接口鉴权、Token 刷新与黑名单。

### 2.2 核心功能

| 功能 | 说明 | 接口 |
|------|------|------|
| Token 签发 | 使用 app_key/app_secret 换取访问 Token | POST /api/auth/token |
| Token 刷新 | 刷新 Token，旧 Token 自动失效 | POST /api/auth/refresh |
| 登出 | 主动登出，Token 加入黑名单 | POST /api/auth/logout |
| 租户列表 | 获取所有启用的租户列表 | GET /api/auth/tenants |
| 管理员登录 | 管理后台登录认证（RSA 加密 app_secret 传输） | GET /api/auth/public-key → POST /api/auth/token（encrypted=true） |

### 2.3 Token 结构

> 自研 HMAC-SHA256 签名 Token（**非标准 JWT**，无 header 段、无 role 字段）。

```
Token = base64url(payload) . HMAC-SHA256(payload, app_secret_hash)
```

**Payload 字段**：
| 字段 | 类型 | 说明 |
|------|------|------|
| tid | string | 租户 ID |
| exp | int64 | 过期时间戳 |
| nonce | string | 16 字节随机数，确保唯一性 |

**角色判定**：角色不写入 Token，由服务端 `tenants.is_platform_admin` 实时判定（平台管理员 / 租户管理员 / 业务用户），修改权限即时生效。

### 2.4 认证流程

```
1. 第三方后端 → POST /api/auth/token (app_key + app_secret + user_id)
2. Go 网关 → 校验 app_key/app_secret → 签发 Token (含 tenant_id)
3. 第三方后端 → 返回 Token 给前端
4. 前端 → 请求 API 时携带 Token (Authorization: Bearer xxx)
5. Go 中间件 → 校验 Token 签名、过期时间、黑名单
6. Go 中间件 → 从 Token 提取 tenant_id，注入请求上下文
7. Handler → 使用 tenant_id 进行数据隔离查询
```

### 2.5 安全机制

- **签名算法**：HMAC-SHA256，签名密钥 = 租户 app_secret 的 sha256 哈希（存 DB，不存明文）
- **登录加密**：管理端登录支持 RSA-OAEP 加密 app_secret 传输（`GET /api/auth/public-key` 下发公钥）
- **过期时间**：默认 24 小时，可配置（`auth.token_ttl`）
- **黑名单**：Redis 存储（`cs:tok:bl:{token}`），TTL 自动过期，多实例全局一致；查询失败按已拉黑处理（fail-closed）
- **登录防爆破**：Redis 计数，同一 IP+app_key 连续失败 5 次锁 10 分钟（429）
- **Nonce 唯一性**：每次签发包含 16 字节随机数，防止重放攻击
- **内部接口鉴权**：Go ↔ Agent 使用 X-Internal-Token Header

## 3. 租户管理模块

### 3.1 功能概述
平台管理员管理所有租户，支持租户创建、编辑、启用/禁用、密钥重置。

### 3.2 核心功能

| 功能 | 说明 | 权限 |
|------|------|------|
| 租户列表 | 查看所有租户，支持筛选 | 平台管理员 |
| 创建租户 | 自动生成 app_key/app_secret | 平台管理员 |
| 编辑租户 | 修改租户名称 | 平台管理员 |
| 启用/禁用 | 禁用后租户无法登录 | 平台管理员 |
| 重置密钥 | 重新生成 app_secret | 平台管理员 |
| 租户统计 | 查看工单数量、会话数量 | 平台管理员 |

### 3.3 租户数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 自增主键 |
| tenant_id | varchar(32) | 租户唯一标识，如 t_demo |
| name | varchar(100) | 租户名称 |
| app_key | varchar(64) | 应用 Key，用于认证 |
| app_secret_hash | varchar(128) | app_secret 的哈希值（不存储明文） |
| status | tinyint | 状态：1=启用，0=禁用 |
| is_platform_admin | tinyint | 是否平台管理员：1=是，0=否 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

### 3.4 租户隔离机制

| 数据类型 | 隔离方式 | 说明 |
|---------|---------|------|
| MySQL 业务数据 | tenant_id 字段 + 复合索引 | 所有查询强制带 tenant_id 条件 |
| PostgreSQL Agent 数据 | tenant_id 字段 | Prompt、知识库文档按租户隔离 |
| Qdrant 向量数据 | 独立集合 | 集合名：kb_{tenant_id}（如 kb_t_demo） |
| 认证 | Token 中的 tenant_id | 中间件校验，防止越权访问 |
| 知识库缓存 | tenant_id 前缀 | 缓存 key 包含 tenant_id |

## 4. 智能对话模块

### 4.1 功能概述
基于 AI 大模型的智能客服对话，支持流式输出、知识库检索增强（RAG）、工具调用、多轮上下文理解。

### 4.2 核心功能

| 功能 | 说明 | 技术实现 |
|------|------|---------|
| 智能回复 | AI 自动回复用户问题 | LangGraph + 大模型 |
| 流式输出 | AI 回复逐字输出 | SSE + WebSocket |
| RAG 检索 | 检索知识库增强回答 | Qdrant 向量检索 |
| 工具调用 | 调用业务工具（订单查询等） | LangGraph Tool |
| 上下文理解 | 理解多轮对话上下文 | LangGraph 会话状态 |
| 意图识别 | 识别用户意图，路由处理流程 | 大模型 + Prompt |
| 知识库缓存 | 检索结果缓存 5 分钟 | 内存缓存 + TTL |
| 会话持久化 | 会话状态持久化到 PostgreSQL | LangGraph checkpoint |
| 过期清理 | 自动清理过期会话 | 定时任务 |

### 4.3 对话流程

```
1. 用户发送消息 → WebSocket → Go 网关
2. Go 网关 → 校验 Token、频率限制 → 调用 Agent SSE 流式接口
3. Python Agent → 接收消息 → 开始 LangGraph 智能体流程
4. LangGraph 流程：
   a. 检索知识库（RAG）→ 获取相关文档
   b. 构建 Prompt（系统提示词 + 上下文 + 知识库 + 用户问题）
   c. 调用大模型 → 流式生成回复
   d. 工具调用（如需要）→ 执行工具 → 继续生成
   e. 保存会话状态 → PostgreSQL checkpoint
5. Python Agent → SSE 逐 chunk 推送回复 → Go 网关
6. Go 网关 → WebSocket 逐 chunk 推送给前端
7. 前端 → 逐字渲染 AI 回复
8. 完成后 → 保存消息记录 → MySQL
```

### 4.4 流式输出实现

**后端（Python Agent）**：
- 使用 LangGraph `astream(stream_mode="messages")`
- 逐 token 输出，通过 SSE 推送
- 事件类型：`chunk`（内容块）、`end`（完整内容）、`error`（错误）、`interrupt`（转人工中断）

**Go 网关**：
- `CallAgentChatStream` 函数读取 SSE 响应
- 逐 chunk 读取，通过回调函数推送到 WebSocket

**前端**：
- `startStreaming()` 开始流式渲染
- `appendStreamChunk(chunk)` 追加内容块
- `endStreaming(fullText)` 结束流式渲染
- `cancelStreaming()` 取消流式输出

### 4.5 RAG 检索流程

```
1. 用户问题 → Embedding 模型 → 向量
2. 向量 → Qdrant 相似度检索 → Top-K 相关文档片段
3. 文档片段 → 构建上下文 → 注入 Prompt
4. 大模型 → 基于上下文生成回答
5. 缓存检索结果 → 5 分钟 TTL → 相同问题直接返回
```

```
                    ┌──────────┐

                    └────┬─────┘
                         │ 客服接管
                         ▼
                    ┌──────────┐
                    │  处理中   │◄────────┐

                         │ 问题解决        │ 重新打开
```

### 5.5 人工接管流程

```
1. 客服点击"接管对话" → WebSocket 发送接管指令
2. Go 网关 → 更新工单状态为"处理中" → 记录操作日志
3. Go 网关 → 通知用户端"客服已接入"
4. 客服发送消息 → WebSocket → Go 网关 → 推送给用户
5. 用户发送消息 → WebSocket → Go 网关 → 推送给客服
6. 客服点击"结束接管" → 更新工单状态 → AI 恢复自动回复
```

## 6. 知识库管理模块

### 6.1 功能概述
租户级知识库管理，支持文档上传、分类管理、向量索引、重新索引、语义检索。

### 6.2 核心功能

| 功能 | 说明 |
|------|------|
| 文档上传 | 支持 PDF、Word、TXT、Markdown 等格式 |
| 文档列表 | 按分类、状态筛选，查看元信息 |
| 分类管理 | 自定义文档分类，支持分类列表查询 |
| 向量索引 | 自动切分文档、生成向量、写入 Qdrant |
| 重新索引 | 文档更新后重新生成向量 |
| 状态管理 | 索引中/已完成/失败三种状态 |
| 错误信息 | 索引失败时记录错误原因 |
| 语义检索 | 基于向量相似度的语义检索 |
| 租户隔离 | 每个租户独立的 Qdrant 集合 |

### 6.3 文档数据模型

**kb_documents 表（PostgreSQL）**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigserial | 自增主键 |
| doc_id | varchar(64) | 文档唯一 ID（UNIQUE） |
| tenant_id | varchar(64) | 租户 ID |
| title | varchar(255) | 文档标题 |
| file_name | varchar(255) | 原文件名 |
| file_size | int | 文件大小（字节） |
| category | varchar(64) | 分类（默认「默认」） |
| status | smallint | 状态：0=待索引/失败，1=已索引 |
| error_msg | text | 索引失败原因 |
| file_url | varchar(512) | 原文件静态地址（/kb_files/…，nginx 服务） |
| chunk_count | int | 切分块数量 |
| created_at / updated_at | timestamp | 创建/更新时间 |

> 文档原文不存库：上传时提取文本用于索引，原文件落盘共享卷（agent → nginx /kb_files/ 静态服务），下载/预览直接走 file_url。

### 6.4 文档索引流程

```
1. 用户上传文档 → Go 网关 → 保存文件元数据到 PostgreSQL
2. Go 网关 → 调用 Agent 索引接口
3. Python Agent → 读取文档内容 → 文本提取（PDF/Word 等）
4. 文本切分 → 按段落/固定长度切分，保留上下文
5. 每个块 → Embedding 模型 → 生成向量
6. 向量 → Qdrant（租户独立集合）→ 写入向量 + 元数据
7. 更新文档状态 → "已完成" → 记录 chunk_count
8. 失败时 → 更新状态为"失败" → 记录 error_msg
```

### 6.5 语义检索流程

```
1. 用户问题 → Embedding 模型 → 查询向量
2. 查询向量 → Qdrant 相似度检索 → Top-K 相关块
3. 相关块 → 按相似度排序 → 拼接成上下文
4. 上下文 → 注入 Prompt → 大模型生成回答
5. 缓存检索结果 → key = tenant_id + MD5(query) → TTL 5 分钟
```

### 6.6 Qdrant 集合设计

**集合命名**：`kb_{tenant_id}`
- 示例：租户 t_demo 的集合名为 `kb_t_demo`（无租户时兜底 `kb_default`）

**向量配置**：
| 配置项 | 值 | 说明 |
|--------|-----|------|
| 向量维度 | 1536 / 1024 / 768 | 取决于 Embedding 模型（启动时探测） |
| 距离度量 | Cosine | 余弦相似度 |
| 分片数 | 1 | 单节点部署 |
| 复制因子 | 1 | 单节点部署 |

**Payload 字段**：
| 字段 | 类型 | 说明 |
|------|------|------|
| document_id | string | 文档 ID |
| tenant_id | string | 租户 ID |
| chunk_index | int | 块索引 |
| content | string | 块文本内容 |
| category | string | 分类 |
| file_name | string | 文件名 |

## 7. Prompt 管理模块

### 7.1 功能概述
租户级 Prompt 模板管理，支持版本控制、回滚、变量配置、系统提示词设置。

### 7.2 核心功能

| 功能 | 说明 |
|------|------|
| Prompt 列表 | 查看所有 Prompt 模板，按类型筛选 |
| 创建编辑 | 可视化编辑 Prompt 内容，支持变量占位符 |
| 版本历史 | 每次修改自动保存版本，记录修改时间 |
| 版本回滚 | 一键回滚到历史版本 |
| 变量配置 | 支持 {{question}}、{{context}} 等变量 |
| 系统提示词 | 配置 Agent 系统提示词、角色设定 |
| 租户隔离 | Prompt 按 tenant_id 隔离 |

### 7.3 Prompt 数据模型

**prompt_versions 表（PostgreSQL）**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 版本 ID |
| tenant_id | varchar(32) | 租户 ID |
| prompt_key | varchar(100) | Prompt 标识（如 system_prompt） |
| name | varchar(200) | Prompt 名称 |
| content | text | Prompt 内容 |
| version | int | 版本号 |
| variables | jsonb | 变量列表 |
| created_at | timestamp | 创建时间 |
| created_by | varchar(50) | 创建人 |

### 7.4 版本管理机制

```
1. 创建 Prompt → 版本号 = 1 → 标记为当前版本
2. 编辑 Prompt → 创建新版本 → 版本号 +1 → 标记为当前版本
3. 历史版本保留 → 不删除 → 可查看、可回滚
4. 回滚 → 将指定版本内容复制为新版本 → 版本号 +1
5. Agent 调用时 → 读取当前版本（最大版本号）
```

### 7.5 支持的变量

| 变量 | 说明 | 示例值 |
|------|------|--------|
| {{question}} | 用户问题 | "如何退货？" |
| {{user_name}} | 用户名 | "张三" |
| {{context}} | 知识库检索上下文 | "退货政策：7天无理由..." |
| {{history}} | 对话历史 | "用户：你好\nAI：您好" |
| {{date}} | 当前日期 | "2026-09-06" |
| {{tenant_name}} | 租户名称 | "XX商城" |

### 7.6 Prompt 类型

| 类型 | 说明 | 使用场景 |
|------|------|---------|
| system_prompt | 系统提示词 | 定义 AI 角色、行为规范、回答风格 |
| welcome_prompt | 欢迎语 | 用户首次进入时的欢迎消息 |
| fallback_prompt | 兜底回复 | 知识库未命中时的回复 |
| transfer_prompt | 转人工提示 | 引导用户转人工客服的提示 |
| custom_prompt | 自定义 Prompt | 业务自定义的 Prompt 模板 |

## 8. 模型配置模块

### 8.1 功能概述
平台级和租户级模型配置，支持多模型提供商、API Key 管理、默认模型设置、Embedding 模型配置。

### 8.2 核心功能

| 功能 | 说明 | 权限 |
|------|------|------|
| 模型提供商管理 | 定义提供商、Base URL、模型列表 | 平台管理员 |
| 平台默认模型 | 设置平台默认对话/Embedding 模型 | 平台管理员 |
| 租户模型配置 | 租户使用自己的 API Key | 租户管理员 |
| API Key 加密 | AES 加密存储，不返显明文 | 系统 |
| 密钥掩码显示 | 列表页只显示掩码后的 Key | 系统 |
| 模型测试 | 测试模型连接是否正常 | 租户管理员 |

### 8.3 数据模型

**model_providers 表（MySQL）**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 提供商 ID |
| provider_key | varchar(64) | 提供商代码（openai/deepseek/qwen/…） |
| provider_name | varchar(128) | 提供商名称 |
| default_model | varchar(128) | 默认模型 |
| default_api_base | varchar(256) | 默认 API Base URL |
| provider_type | varchar(32) | 类型：chat / embedding |
| sort_order | int | 排序 |
| status | tinyint | 状态：1=启用，0=禁用 |

> **提供商表不存 API Key**（仅元信息）。API Key 一律 AES 加密存于 `tenants` 表的 BYOK 字段，由模型配置模块统一管理。

**tenants 表 BYOK 模型字段（MySQL，替代原 tenant_model_config 表）**：
| 字段 | 说明 |
|------|------|
| model_provider / model_name / model_api_key / model_api_base | 对话模型配置（provider=platform 跟随平台 / custom 自定义） |
| embedding_provider / embedding_model_name / embedding_api_key / embedding_api_base / embedding_mode | Embedding 模型配置 |
| llm_provider_id / embedding_provider_id | 关联 model_providers.id |
| chat_input_cache_price / chat_input_price / chat_output_price / embedding_price | 单价（元/百万 tokens，0=未定价） |
| max_concurrent_sessions / daily_message_limit / max_kb_docs / max_kb_size_mb | 租户配额（0=不限） |

> **平台默认模型 = 平台管理员租户（t_admin）的模型配置**（单一数据源）；租户选择「跟随平台」即继承，选择自定义即 BYOK 覆盖。

### 8.4 支持的模型类型

| 类型 | 说明 | 示例模型 |
|------|------|---------|
| chat | 对话模型 | gpt-4o、qwen-plus、deepseek-chat |
| embedding | 向量模型 | text-embedding-3-small、text-embedding-v3、qwen3.7-text-embedding-flash |

> 提供商按 `provider_type` 区分 chat / embedding；接入 OpenAI 兼容接口即可扩展更多模型。

### 8.5 API Key 安全机制

- **加密存储**：AES-256 加密存储数据库
- **不返显**：API 接口不返回明文 Key
- **掩码显示**：前端显示 `sk-...xxxx` 格式
- **租户隔离**：每个租户使用自己的 API Key，独立计费
- **平台兜底**：租户未配置时使用平台默认 Key

## 9. WebSocket 通信模块

### 9.1 功能概述
WebSocket 长连接，支持实时消息推送、AI 流式输出、人工客服实时通知、连接管理与频率限制。

### 9.2 核心功能

| 功能 | 说明 |
|------|------|
| 长连接管理 | Hub 模式管理所有 WebSocket 连接 |
| 用户端连接 | 用户接收 AI 回复、人工客服消息 |
| 客服端连接 | 客服接收新工单通知、新消息推送 |
| 流式输出 | AI 回复逐 chunk 推送 |

| 连接状态 | 实时监控连接数，Prometheus 指标 |
| 频率限制 | 单 IP/单用户连接数、消息频率限制 |
| 断线重连 | 前端自动重连机制 |
| 心跳检测 | 定时心跳，检测连接存活 |

### 9.3 Hub 架构

```
                    ┌─────────────┐
                    │  WebSocket  │
                    │    Hub      │
                    └──────┬──────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
    ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
    │ 用户连接池  │   │ 客服连接池  │   │  管理连接   │
    │ (user_id)  │   │ (agent_id) │   │  (admin)   │
    └─────┬─────┘   └─────┬─────┘   └─────┬─────┘
          │                │                │
    ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
    │  用户前端   │   │  客服后台   │   │  管理后台   │
    └───────────┘   └───────────┘   └───────────┘
```

### 9.4 消息类型

## 10. 第三方集成模块

### 10.1 功能概述
提供多种接入方式，支持 PC 网站、H5、APP、小程序等平台快速集成智能客服。

### 10.2 接入方式

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| SDK 嵌入 | PC/H5 网站 | 轻量、可定制、无 iframe 限制 | 需要前端开发 |
| iframe 嵌入 | 快速集成 | 简单、独立、升级方便 | 样式定制受限 |
| API 直接调用 | APP/小程序 | 灵活、完全可控 | 需要自行实现 UI |
| WebSocket 直连 | 深度集成 | 实时性好 | 需要处理连接管理 |

### 10.3 SDK (cs-chat.js)

**功能特性**：
- 悬浮客服按钮，可配置位置（左/右）
- 点击弹出对话窗口，可配置大小
- 支持主题色自定义
- 支持标题、欢迎语自定义
- 自动管理 WebSocket 连接
- 自动重连机制
- 流式输出渲染
- 消息已读状态
- 转人工功能

**初始化参数**：
| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| token | string | 是 | - | 访问 Token |
| user_id | string | 是 | - | 用户唯一标识 |
| title | string | 否 | 在线客服 | 窗口标题 |
| theme | string | 否 | #1890ff | 主题色 |
| position | string | 否 | right | 按钮位置 |
| welcome_message | string | 否 | 您好... | 欢迎语 |
| width | int | 否 | 400 | 窗口宽度 |
| height | int | 否 | 600 | 窗口高度 |

### 10.4 接入流程

```
1. 租户管理员 → 管理后台 → 获取 app_key/app_secret
2. 第三方后端 → 集成 Token 换取接口 → 安全存储 app_secret
3. 用户登录 → 第三方后端 → 调用 /api/auth/token → 获取用户 Token
4. 第三方前端 → 引入 cs-chat.js → 初始化 SDK（传入 Token）
5. 用户点击客服按钮 → 弹出对话窗口 → 开始对话
6. SDK → 自动建立 WebSocket 连接 → 发送/接收消息
```

### 10.5 安全建议

- **app_secret 不暴露**：只在第三方后端使用，绝不下发到前端
- **Token 后端换取**：前端通过后端接口获取 Token，避免 app_key/app_secret 泄露
- **Token 过期处理**：前端检测 Token 过期，自动向后端重新获取
- **user_id 规范**：使用第三方系统的用户 ID，确保唯一性
- **HTTPS 部署**：生产环境必须使用 HTTPS/WSS

## 13. Redis 基础设施模块（强制依赖）

> 自 2026-09 起 Redis 为**强制依赖**：Go/Agent 启动时 fail-fast（Redis 不可用拒绝启动）；运行期查询失败 fail-closed（登录被拒、黑名单按已拉黑处理）。生产必须配套 Redis 高可用（云 Redis 或主从+Sentinel），详见《06-多实例扩展与Redis缓存失效广播方案.md》。

| 用途 | Key / Channel | 说明 |
|------|---------------|------|
| 登录防爆破 | `cs:login:fail:{ip:app_key}` | 同一 IP+app_key 连续失败 5 次锁 10 分钟（429） |
| Token 黑名单 | `cs:tok:bl:{token}` | 登出/刷新后失效，TTL 自动过期，多实例全局一致 |
| 模型配置缓存失效广播 | `cs:model:cache:invalidate`（pub/sub） | Go 保存模型配置后发布，所有 Agent 实例订阅清除本地缓存（scope 粒度） |
| 知识库索引队列 | `cs:kb:index:queue` | 知识库上传/重索引异步消费（kb_index_worker） |
| 会话清理分布式锁 | SETNX | 多实例互斥执行 cleanup_sessions（锁不可用跳过本轮） |
