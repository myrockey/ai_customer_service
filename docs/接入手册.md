## 1. 产品概述

智能客服系统是一套基于大语言模型的 SaaS 客服解决方案，支持：

- **AI 自动应答**：7×24 小时自动回复用户咨询，基于知识库检索增强（RAG）
- **人工接管**：AI 无法解决时一键转人工，客服在后台实时对话
- **工单管理**：完整工单流转，支持待处理 / 接管中 / 已完成
- **知识库管理**：上传文档，AI 基于企业私有知识回答
- **Prompt 管理**：自定义 AI 人设和回答风格
- **多租户隔离**：每个客户数据完全隔离，互不干扰

## 2. 接入架构

```
第三方系统（客户）                          智能客服平台
┌──────────────────────────┐               ┌──────────────────────────┐
│  前端页面                 │               │  Go 网关 (端口 8080)     │
│  ┌────────────────────┐  │  iframe/跳转  │  ├─ POST /api/auth/token │
│  │ 客服浮窗（iframe）  │──┼──────────────►│  ├─ POST /api/user/chat  │
│  └────────────────────┘  │               │  ├─ GET  /api/admin/...   │
│                          │               │  └─ WS   /ws/user          │
│  服务端                  │  app_key/secret│                           │
│  ┌────────────────────┐  │  换 access_token│  Agent (AI 引擎)        │
│  │ /your-api/get-token│──┼──────────────►│  ├─ 大模型对话            │
│  └────────────────────┘  │               │  ├─ 知识库检索 (Qdrant)   │
│                          │               │  └─ Prompt 管理 (PG)       │
└──────────────────────────┘               └──────────────────────────┘
```

**核心原则**：`app_secret` 只存在于第三方服务端，前端只持有短期有效的 `access_token`。

## 4. 步骤一：创建租户获取密钥

### 4.1 登录管理后台

访问平台管理地址：`https://你的客服域名/admin/`

使用平台管理员账号登录（由平台运营方提供）。

### 4.2 创建租户

1. 点击左侧 **「租户管理」**
2. 点击 **「+ 新建租户」** 按钮
3. 填写：
   - **租户名称**（必填）：如"深圳XX电商"、"XX科技官网"
   - **app_key**（可选）：留空自动生成，建议用品牌缩写如 `xx_shop_key`
4. 点击 **「确认创建」**

### 4.3 保存密钥

创建成功后会弹出密钥提示框，**包含以下三项，仅此一次显示，请立即复制保存**：

```
tenant_id:  t_xxxxxxxxxxxxxxxx
app_key:    xx_shop_key
app_secret: xxxxxxxxxxxxxxxxxxxxxxxx
```

> ⚠️ **重要**：app_secret 刷新页面后无法再次查看。如遗失，可在租户列表点击「重置密钥」生成新密钥（旧密钥立即失效）。

## 5. 步骤二：服务端换取 Token

### 5.1 为什么必须在服务端换 token？

- `app_secret` 是租户的最高权限凭证，泄露后任何人都能冒充你的租户调用 API
- 前端代码（JavaScript）对用户可见，浏览器开发者工具可直接查看
- 因此 **必须在第三方自己的服务端** 用 app_key + app_secret 换取 token，再把 token 传给前端

### 5.2 换 token 接口

**请求**：

```
POST https://你的客服域名/api/auth/token
Content-Type: application/json

{
  "app_key": "xx_shop_key",
  "app_secret": "xxxxxxxxxxxxxxxx"
}
```

**成功响应**：

```json
{
  "code": 0,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 86400,
    "tenant_id": "t_xxxxxxxx",
    "is_platform_admin": false
  }
}
```

**失败响应**：

```json
{
  "code": 401,
  "msg": "无效的 app_key 或 app_secret"
}
```

### 5.3 代码示例

#### Python (FastAPI / Flask)

```python
import requests
import time
from threading import Lock

CS_BASE_URL = "https://你的客服域名"
APP_KEY = "xx_shop_key"
APP_SECRET = "xxxxxxxxxxxxxxxx"  # 从环境变量读取，不要硬编码

_token_cache = {"token": None, "expiry": 0}
_token_lock = Lock()

def get_cs_token() -> str:
    """获取客服系统 access_token（带缓存，提前30分钟刷新）"""
    with _token_lock:
        now = time.time()
        if _token_cache["token"] and now < _token_cache["expiry"] - 1800:
            return _token_cache["token"]

        resp = requests.post(
            f"{CS_BASE_URL}/api/auth/token",
            json={"app_key": APP_KEY, "app_secret": APP_SECRET},
            timeout=10
        )
        data = resp.json()
        if data["code"] != 0:
            raise Exception(f"换token失败: {data['msg']}")

        _token_cache["token"] = data["data"]["token"]
        _token_cache["expiry"] = now + data["data"]["expires_in"]
        return _token_cache["token"]


# FastAPI 示例：给前端提供 token 接口
from fastapi import FastAPI
app = FastAPI()

@app.get("/api/get-cs-token")
def get_cs_token_api():
    return {"token": get_cs_token()}
```

#### PHP

```php
<?php
class CsTokenService {
    private string $baseUrl = 'https://你的客服域名';
    private string $appKey = 'xx_shop_key';
    private string $appSecret = 'xxxxxxxxxxxxxxxx'; // 从环境变量读取
    private ?string $cachedToken = null;
    private int $tokenExpiry = 0;

    public function getToken(): string {
        if ($this->cachedToken && time() < $this->tokenExpiry - 1800) {
            return $this->cachedToken;
        }

        $ch = curl_init($this->baseUrl . '/api/auth/token');
        curl_setopt_array($ch, [
            CURLOPT_POST => true,
            CURLOPT_POSTFIELDS => json_encode([
                'app_key' => $this->appKey,
                'app_secret' => $this->appSecret,
            ]),
            CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT => 10,
        ]);
        $resp = json_decode(curl_exec($ch), true);
        curl_close($ch);

        if ($resp['code'] !== 0) {
            throw new Exception('换token失败: ' . $resp['msg']);
        }

        $this->cachedToken = $resp['data']['token'];
        $this->tokenExpiry = time() + $resp['data']['expires_in'];
        return $this->cachedToken;
    }
}

// 使用示例
$service = new CsTokenService();
echo json_encode(['token' => $service->getToken()]);
```

#### Go

```go
package csclient

import (
    "bytes"
    "encoding/json"
    "fmt"
    "net/http"
    "sync"
    "time"
)

type TokenManager struct {
    BaseURL   string
    AppKey    string
    AppSecret string

    mu        sync.Mutex
    token     string
    expiresAt time.Time
}

func (tm *TokenManager) GetToken() (string, error) {
    tm.mu.Lock()
    defer tm.mu.Unlock()

    if tm.token != "" && time.Now().Before(tm.expiresAt.Add(-30*time.Minute)) {
        return tm.token, nil
    }

    body, _ := json.Marshal(map[string]string{
        "app_key":    tm.AppKey,
        "app_secret": tm.AppSecret,
    })
    resp, err := http.Post(tm.BaseURL+"/api/auth/token",
        "application/json", bytes.NewReader(body))
    if err != nil {
        return "", err
    }
    defer resp.Body.Close()

    var result struct {
        Code int    `json:"code"`
        Msg  string `json:"msg"`
        Data struct {
            Token     string `json:"token"`
            ExpiresIn int    `json:"expires_in"`
        } `json:"data"`
    }
    if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
        return "", err
    }
    if result.Code != 0 {
        return "", fmt.Errorf("换token失败: %s", result.Msg)
    }

    tm.token = result.Data.Token
    tm.expiresAt = time.Now().Add(time.Duration(result.Data.ExpiresIn) * time.Second)
    return tm.token, nil
}
```

#### Node.js (Express)

```javascript
const axios = require('axios');

const CS_BASE_URL = 'https://你的客服域名';
const APP_KEY = 'xx_shop_key';
const APP_SECRET = process.env.CS_APP_SECRET; // 从环境变量读取

let tokenCache = { token: null, expiry: 0 };

async function getCsToken() {
  const now = Date.now();
  if (tokenCache.token && now < tokenCache.expiry - 30 * 60 * 1000) {
    return tokenCache.token;
  }

  const resp = await axios.post(`${CS_BASE_URL}/api/auth/token`, {
    app_key: APP_KEY,
    app_secret: APP_SECRET,
  }, { timeout: 10000 });

  if (resp.data.code !== 0) {
    throw new Error(`换token失败: ${resp.data.msg}`);
  }

  tokenCache.token = resp.data.data.token;
  tokenCache.expiry = now + resp.data.data.expires_in * 1000;
  return tokenCache.token;
}

// Express 路由
app.get('/api/get-cs-token', async (req, res) => {
  try {
    res.json({ token: await getCsToken() });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});
```

### 5.4 Token 缓存最佳实践

| 建议 | 说明 |
|------|------|
| 缓存 token | token 有效期 24 小时，不要每次前端请求都换 |
| 提前刷新 | 在 token 过期前 30 分钟主动刷新，避免用户遇到过期 |
| 并发保护 | 多线程/多进程环境下加锁，避免同时发起多个换 token 请求 |
| 分布式部署 | 多实例部署时用 Redis 共享 token，避免每个实例各自换 |
| 失败重试 | 换 token 失败时重试 2-3 次，间隔 1 秒 |

## 6. 步骤三：前端嵌入客服浮窗

### 6.0 接入方式选择指南

智能客服系统提供 **5 种前端接入方式**，根据你的技术栈和需求选择：

| 方式 | 适用场景 | 接入成本 | 定制能力 | 推荐度 |
|------|---------|---------|---------|--------|
| **SDK 接入** | PC 网站、有定制需求、生产环境 | 低（引入 JS） | 强（API/事件/样式） | ⭐⭐⭐⭐⭐ |
| iframe 嵌入 | 快速验证、零代码接入 | 极低（一行标签） | 弱 | ⭐⭐⭐ |
| 页面跳转 | 移动端 H5 全屏 | 低 | 弱 | ⭐⭐⭐ |
| 微信小程序 | 小程序端 | 中 | 中 | ⭐⭐⭐ |
| App WebView | iOS/Android App | 中 | 中 | ⭐⭐⭐ |

**SDK vs 直接 iframe 对比**：

| 维度 | SDK (cs-chat.js) | 直接 iframe 嵌入 pc.html |
|------|-------------------|------------------------|
| 浮窗按钮 | ✅ 内置，可定制样式/位置/图标 | ❌ 需自己实现 |
| 弹窗动画 | ✅ 内置滑入动画 | ❌ 需自己实现 |
| JS API | ✅ open/close/sendText/setToken | ❌ 需 postMessage 手动通信 |
| 事件监听 | ✅ message/handoff/open/close | ❌ 需 postMessage 手动监听 |
| 移动端适配 | ✅ 自动全屏弹窗 | ❌ 需自己处理 |
| token 管理 | ✅ 支持自动换票 | ❌ 需自己处理 |
| 样式隔离 | ✅ Shadow DOM 不污染页面 | ✅ iframe 完全隔离 |
| 适用场景 | 生产环境、有定制需求 | 快速接入、App WebView |

> **架构说明**：SDK 内部也是用 iframe 加载 pc.html，SDK 负责外壳（浮窗按钮+弹窗+API+事件），pc.html 负责聊天内核（WebSocket+消息渲染）。两者共用同一套代码，维护成本低。

### 6.1 方式一：SDK 接入（生产推荐）

SDK 是生产环境的推荐接入方式，提供浮窗按钮、弹窗动画、JS API、事件监听等完整能力。

#### 6.1.1 最简单接入（data-* 自动初始化）

只需在页面底部引入一行 script 标签，SDK 自动渲染浮窗按钮：

```html
<!-- 在 </body> 前引入 -->
<script src="https://你的客服域名/sdk/cs-chat.js"
        data-server="https://你的客服域名"
        data-token="宿主后端换取的token"
        data-title="在线客服"
        data-theme="#1890ff"
        data-button-icon="💬"
        data-button-text="客服"
        data-position="right"
        data-width="380"
        data-height="560">
</script>
```

**data-* 属性列表**：

| 属性 | 说明 | 默认值 |
|------|------|--------|
| `data-server` | 客服系统地址（可选，同域部署时自动推导当前域名/端口，跨域部署才需显式指定） | 当前页面域名 |
| `data-token` | access_token（推荐：宿主后端换取后传入） | - |
| `data-app-key` | app_key（配合 app-secret 自动换票，仅演示用） | - |
| `data-app-secret` | app_secret（生产勿用，会暴露在前端） | - |
| `data-tenant-id` | 租户ID（直传 token 时建议传） | - |
| `data-title` | 客服窗口标题 | 在线客服 |
| `data-theme` | 主题色（十六进制） | #1890ff |
| `data-position` | 浮窗位置：right / left | right |
| `data-width` | 弹窗宽度（px） | 380 |
| `data-height` | 弹窗高度（px） | 560 |
| `data-offset-x` | 距侧边距离（px） | 20 |
| `data-offset-y` | 距底部距离（px） | 20 |
| `data-button-icon` | 按钮图标（emoji 或文字） | 💬 |
| `data-button-text` | 按钮文字（留空只显示图标） | - |
| `data-auto-show` | 是否自动显示浮窗按钮 | true |
| `data-manual` | 设为 true 时不自动初始化，需手动调用 init() | false |

#### 6.1.2 手动初始化（推荐，可调用 API）

```html
<script src="https://你的客服域名/sdk/cs-chat.js" data-manual="true"></script>
<script>
  // 从你的服务端获取 token（生产环境必须在后端换 token）
  async function initCsChat() {
    const resp = await fetch('/api/get-cs-token');
    const data = await resp.json();

    CSCHAT.init({
      server: 'https://你的客服域名',
      token: data.token,           // 服务端换取的 token
      tenant_id: data.tenant_id,   // 租户ID
      title: '在线客服',
      theme: '#1890ff',
      position: 'right',
      width: 380,
      height: 560,
      button_icon: '💬',
      button_text: '客服'
    });

    // 事件监听
    CSCHAT.on('ready', function(data) {
      console.log('客服就绪，user_id:', data.user_id);
    });
    CSCHAT.on('message', function(data) {
      console.log('收到消息:', data.role, data.content);
    });
    CSCHAT.on('handoff', function(data) {
      console.log('转人工成功，工单号:', data.ticket_no);
    });
    CSCHAT.on('open', function() { console.log('客服窗口打开'); });
    CSCHAT.on('close', function() { console.log('客服窗口关闭'); });
  }

  initCsChat();
</script>
```

### 6.3 方式三：移动端 H5（全屏客服页面）

**适用场景**：手机浏览器、微信内 H5 页面、移动端官网。

**为什么用全屏页面而不是浮窗？**
- 移动端屏幕小，浮窗按钮可能遮挡内容，弹窗体验差
- `h5/chat.html` 已专门做移动端适配（安全区域、100dvh、触摸优化、返回按钮、快捷问题）
- 全屏页面用户体验更好，类似微信客服对话

**完整接入代码**：

```html

// ============ user_id 管理（localStorage 持久化） ============
function getCsUserId() {
```

```javascript
    if (!openid) {
```

## 7. 步骤四：user_id 生成规则

### 7.1 为什么 user_id 很重要？

`user_id` 是客服系统识别用户的唯一标识，决定了：
- 会话历史是否保留（同一 user_id 能看到之前的对话记录）
- 工单是否归属正确（人工客服看到的是这个用户的历史工单）
- AI 记忆是否连贯（LangGraph 会话状态按 user_id 持久化）

### 7.2 推荐方案

| 用户场景 | user_id 格式 | 示例 | 说明 |
|----------|-------------|------|------|
| 已登录用户 | `user_{你的系统用户ID}` | `user_12345` | 直接用自有系统的用户ID，加前缀防枚举 |
| 未登录游客 | `guest_{时间戳}_{随机串}` | `guest_1725500000_a3f2k9` | 首次访问生成，存入 localStorage/cookie，后续复用 |
| 微信小程序 | `wx_{openid}` | `wx_o6xXXXXXXXX` | 用 openid，同一用户固定不变 |
| App | `app_{设备ID或用户ID}` | `app_abc123def456` | 登录后用用户ID，未登录用设备ID |

### 7.3 游客 user_id 前端实现

```javascript
function getCsUserId() {
  // 1. 已登录用户优先用系统ID
  if (window.userInfo && window.userInfo.id) {
    return 'user_' + window.userInfo.id;
  }
  // 2. 游客：从 localStorage 读取，没有则生成
  let uid = localStorage.getItem('cs_user_id');
  if (!uid) {
    uid = 'guest_' + Date.now() + '_' + Math.random().toString(36).slice(2, 8);
    localStorage.setItem('cs_user_id', uid);
  }
  return uid;
}
```

### 7.4 注意事项

- ✅ **同一用户在同一设备上 user_id 必须固定**，否则每次打开都是新会话
- ✅ **user_id 加前缀**（`user_` / `guest_` / `wx_`），避免与其他租户的用户ID冲突
- ❌ **不要用可枚举的自增ID**（如 `1`、`2`、`3`），可能被其他租户猜测
- ❌ **不要每次打开都生成新 user_id**，否则会话历史无法保留
- ⚠️ **用户登录后建议切换为系统用户ID**，并可将游客历史会话迁移（如需）

## 9. 安全规范

### 9.1 密钥安全

| 规则 | 说明 |
|------|------|
| app_secret 不出现在前端 | 前端代码、浏览器请求、Git 仓库中绝不能出现 app_secret |
| app_secret 放环境变量 | 服务端通过环境变量或配置中心读取，不硬编码在代码中 |
| 定期轮换密钥 | 建议每 3-6 个月在管理后台重置一次 app_secret |
| 最小权限原则 | 每个业务系统使用独立租户，不要共用 app_key/app_secret |

### 9.2 传输安全

| 规则 | 说明 |
|------|------|
| 生产环境必须 HTTPS | 所有 API 请求和 WebSocket 连接必须使用 HTTPS / WSS |
| 禁止 HTTP 明文传输 | HTTP 环境下 token 可能被中间人截获 |
| iframe 安全沙箱 | 嵌入 iframe 时建议加 `sandbox="allow-scripts allow-same-origin"` |

### 9.3 Token 安全

| 规则 | 说明 |
|------|------|
| Token 不持久化到前端 | 前端获取 token 后仅用于当前会话，刷新页面重新从服务端获取 |
| Token 有效期 24 小时 | 即使泄露，有效期内有效，过期自动失效 |
| 服务端验证来源 | 换 token 接口建议校验请求来源（Referer / 内网IP限制） |

## 10. 部署与跨域配置

### 10.1 对外端口可调（不固定 8080）

服务对外端口由环境变量 `HTTP_PORT` 控制（nginx 统一入口）：

```bash
# 默认 8080
docker compose up -d

# 修改为 8088（或任意未被占用的端口）
HTTP_PORT=8088 docker compose up -d
```

修改后访问地址整体变化，前端（管理后台 / 客服页面 / SDK）**无需改任何配置**——所有页面均使用同域相对路径（`/api`、`/ws`、`/chat/`、`/admin/`），由 nginx 反代到后端。

### 10.2 前端为什么不需要配 API 地址

| 页面 | 请求方式 | 说明 |
|------|---------|------|
| 管理后台 `/admin/` | 同域相对路径 `/api` | nginx 反代到 Go |
| 客服页面 `/chat/pc.html`、`/chat/h5.html` | 自动推导 `location.host` | URL 可不传 `server` 参数 |
| SDK `cs-chat.js` | `server` 缺省时回退 `location.origin` | 同域部署零配置 |

> 只要第三方把客服页面/API 与自己的网站**同域部署**（或都走客服系统域名），就不会产生跨域问题。

### 10.3 跨域（第三方网站直连 API）

第三方网站**跨域**直接调用客服系统 API（不走客服系统 nginx 反代）时，需配置 CORS 白名单：

```bash
# .env 或部署环境变量（逗号分隔多个域名）
CORS_ALLOW_ORIGINS=https://shop.example.com,https://app.example.com
```

- 配置后 Go 网关会为这些来源返回 CORS 头（`Access-Control-Allow-Origin` 等）
- 未配置时仅放行本地开发地址；**同源访问不受 CORS 限制，无需配置**
- 生产建议：优先同域部署（推荐），跨域仅用于特殊情况

### 10.4 配置归拢

所有部署配置集中在 `.env`（docker compose 自动读取）：

```bash
# 对外 HTTP 端口
HTTP_PORT=8080
# CORS 跨域白名单（逗号分隔；空=仅本地开发地址）
CORS_ALLOW_ORIGINS=
# 数据库、模型密钥、内部 token 等（见 .env 全文）
```

## 11. 常见问题

### Q1：前端直接用 app_key/app_secret 换 token 可以吗？

**不可以。** app_secret 出现在前端代码中，任何人通过浏览器开发者工具都能看到，然后用你的 app_secret 调用 API、查看你的工单数据。必须在服务端换 token。

### Q2：token 过期了怎么办？

token 有效期 24 小时。建议在服务端缓存 token，并在过期前 30 分钟主动刷新。前端每次打开客服浮窗时从服务端获取最新 token，不需要关心过期问题。

### Q3：同一用户在不同设备上会话能同步吗？

可以。只要 user_id 相同（如登录用户用系统用户ID），在任何设备上打开客服浮窗都能看到历史会话记录。

### Q4：iframe 嵌入后客服页面加载慢怎么办？

- 确保客服系统服务器与第三方网站网络延迟低（建议同区域部署）
- 客服页面已做静态资源 CDN 加速
- 可在用户 hover 客服按钮时预加载 iframe（设置 src 但不显示）

### Q5：如何自定义客服浮窗的样式？

- 悬浮按钮的样式完全由第三方自己控制（上面的代码可修改颜色、大小、位置）
- 客服对话窗口的样式由客服系统提供主题定制（联系平台运营方配置品牌色、Logo）

### Q6：转人工后，人工客服在哪里回复？

人工客服登录平台管理后台 `https://你的客服域名/admin/`（使用该租户的 app_key/app_secret 登录），在「工单管理」中查看和回复用户消息。

### Q7：支持哪些大模型？

当前支持 OpenAI 兼容接口的大模型（如 GPT-4、DeepSeek、通义千问等），具体模型由平台运营方配置。

### Q8：部署后改了对外端口，前端报错/登录失败？

前端全部走同域相对路径（`/api`、`/ws`），端口变化**无需改前端**。请确认：
1. 用 `HTTP_PORT=<新端口> docker compose up -d` 重启（nginx 容器会重新映射）
2. 浏览器访问 `http://服务器IP:<新端口>/admin/` 和 `/chat/pc.html` 确认可用
3. 若第三方网站嵌入的 SDK 之前写死了 `data-server="http://xxx:8080"`，改为不带端口或 `data-server` 留空（自动跟随页面域名）

### Q9：第三方网站直接调客服 API 报 CORS 错误？

同域部署不会报 CORS（页面与 API 同源）。跨域直连时在部署环境配置白名单：

```bash
CORS_ALLOW_ORIGINS=https://你的第三方网站域名
docker compose up -d
```

常见错误 "Provisional headers are shown" / "Failed to fetch" 通常是**请求地址写死为 `127.0.0.1:8080` 或 `localhost:8080`** 导致（那是指用户浏览器本机），请改为同域相对路径或空 `server`。
