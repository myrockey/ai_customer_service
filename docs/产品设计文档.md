# 智能客服系统 - 产品设计文档

## 1. 产品概述

### 1.1 产品定位
智能客服系统是一款基于 AI 大模型的多租户 SaaS 客服平台，支持智能对话、人工客服接管、知识库管理、Prompt 管理等核心功能。系统采用产品化设计，可快速集成到第三方网站、APP、小程序等平台。

### 1.2 核心价值
- **降本增效**：AI 自动回复 80%+ 常见问题，减少人工客服工作量
- **7x24 小时服务**：AI 客服全天候在线，用户随时获得响应
- **多租户隔离**：平台化架构，支持多企业独立使用，数据安全隔离
- **灵活集成**：提供 SDK、iframe、API 多种接入方式，快速集成到业务系统
- **可观测性**：完整的日志、监控、链路追踪体系，保障系统稳定运行

### 1.3 目标用户
- **平台管理员**：管理租户、模型配置、系统监控
- **租户管理员**：管理知识库、Prompt、工单、客服人员
- **客服人员**：处理用户咨询、人工接管对话
- **终端用户**：通过客服窗口获取 AI 或人工服务
- **第三方开发者**：将智能客服集成到自己的业务系统

### 2.2 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端（管理端） | Vue3 + Vite | 单页应用（admin-app/），构建产物输出 web/admin/dist |
| 前端（用户端/SDK） | 原生 HTML/CSS/JS | 轻量无依赖，SDK 友好 |
| 网关 | Go + Gin | 高性能 HTTP/WebSocket 服务 |
| AI Agent | Python + LangGraph | 智能体编排、工具调用、RAG |
| 业务数据库 | MySQL 8.4 | 租户、工单、消息、配置等业务数据 |
| Agent数据库 | PostgreSQL 16 + pgvector | Prompt、知识库、会话 checkpoint、用量 |
| 向量数据库 | Qdrant | 文档向量存储、语义检索 |
| 缓存/协调 | Redis 7 | 登录防爆破、Token 黑名单、配置失效广播、索引队列、分布式锁（**强制依赖**） |
| 反向代理 | Nginx | 静态资源、API 路由、负载均衡 |
| 日志 | Loki + Promtail | 结构化日志收集、查询 |
| 监控 | Prometheus + Grafana | 指标采集、可视化、告警 |
| 链路追踪 | OpenTelemetry + Jaeger | 全链路 trace_id 透传 |
| 容器化 | Docker Compose | 一键部署、环境一致性 |

### 2.3 架构分工原则

**MySQL（Go 业务层数据）**：
- 租户信息、用户认证
- 工单、消息记录
- 平台配置、模型提供商
- 需要强事务、复杂查询的业务数据

**PostgreSQL（Agent 层数据）**：
- Prompt 模板及版本
- 知识库文档元数据
- LangGraph 会话 checkpoint
- 会话元数据、过期清理

**Qdrant（向量数据）**：
- 知识库文档向量
- 语义检索、相似度匹配
- 按租户隔离集合

## 3. 多租户架构

### 3.1 租户模型

```
平台管理员 (t_admin)
    ├── 租户 A (t_demo)
    │   ├── 知识库（独立 Qdrant 集合）
    │   ├── Prompt（独立配置）
    │   ├── 工单（tenant_id 隔离）
    │   ├── 消息（tenant_id 隔离）
    │   └── 模型配置（独立 API Key）
    ├── 租户 B (t_shop)
    │   └── ...
    └── 租户 C ...
```

### 3.2 租户隔离机制

| 隔离维度 | 实现方式 |
|---------|---------|
| 数据隔离 | MySQL 表 tenant_id 字段 + 复合索引；PG 表 tenant_id 字段；Qdrant 按租户独立集合 |
| 认证隔离 | app_key/app_secret 签发租户 token，token 中包含 tenant_id |
| 权限隔离 | 中间件校验 token 中的 tenant_id，只能访问本租户数据 |
| 知识库隔离 | Qdrant 集合名包含 tenant_id，租户间向量数据完全隔离 |
| Prompt 隔离 | Prompt 表 tenant_id 字段，租户只能管理自己的 Prompt |
| 模型配置隔离 | 模型配置表 tenant_id 字段，租户使用自己的 API Key |

## 4. 核心功能模块

### 4.1 智能对话模块

**功能描述**：基于 AI 大模型的智能客服对话，支持流式输出、知识库检索增强（RAG）、工具调用。

**核心特性**：
- 流式输出：AI 回复逐字输出，提升用户体验
- RAG 检索：自动检索知识库相关文档，增强回答准确性
- 上下文理解：基于 LangGraph 会话状态，理解多轮对话上下文
- 工具调用：支持订单查询、工单创建等业务工具调用
- 意图识别：自动识别用户意图，路由到对应处理流程
- 知识库缓存：检索结果缓存 5 分钟，提升响应速度

**技术实现**：
- 前端：WebSocket 长连接，逐字渲染 AI 回复
- Go 网关：WebSocket 消息处理，调用 Agent SSE 流式接口
- Python Agent：LangGraph 智能体，astream 流式输出

### 4.2 人工客服模块

**功能描述**：人工客服后台，支持工单管理、会话查看、人工接管对话。

**核心特性**：
- 工单列表：按状态、优先级、时间筛选，支持分页
- 工单详情：查看完整对话历史、用户信息、工单操作历史
- 人工接管：一键接管 AI 对话，直接与用户对话
- 优先级管理：高/中/低优先级，支持快速设置
- 状态流转：待处理 → 处理中 → 已解决 → 已关闭
- 操作历史：记录工单所有状态变更、优先级调整
- 实时推送：WebSocket 实时推送新工单、新消息
- 未读标记：消息已读/未读状态，未读数红点提示

### 4.3 知识库管理模块

**功能描述**：租户级知识库管理，支持文档上传、分类管理、向量索引、重新索引。

**核心特性**：
- 文档上传：支持 PDF、Word、TXT、Markdown 等格式
- 文档列表：按分类、状态筛选，查看文档元信息
- 分类管理：自定义文档分类，支持分类列表查询
- 向量索引：自动切分文档、生成向量、写入 Qdrant
- 重新索引：文档内容更新后重新生成向量
- 状态管理：索引中、已完成、失败三种状态
- 错误信息：索引失败时记录错误原因
- 租户隔离：每个租户独立的 Qdrant 集合，数据完全隔离

**技术实现**：
- 文档存储：PostgreSQL kb_documents 表存储元数据
- 向量存储：Qdrant 按租户独立集合
- 索引流程：文档切分 → Embedding 生成 → 向量写入
- 检索流程：Query Embedding → Qdrant 相似度检索 → 上下文增强

### 4.4 Prompt 管理模块

**功能描述**：租户级 Prompt 模板管理，支持版本控制、回滚、变量配置。

**核心特性**：
- Prompt 列表：查看所有 Prompt 模板，按类型筛选
- 创建编辑：可视化编辑 Prompt 内容，支持变量占位符
- 版本历史：每次修改自动保存版本，记录修改时间
- 版本回滚：一键回滚到历史版本
- 变量配置：支持 {{user_name}}、{{question}} 等变量
- 系统提示词：配置 Agent 系统提示词、角色设定
- 租户隔离：Prompt 按 tenant_id 隔离，租户只能管理自己的 Prompt

**技术实现**：
- 数据存储：PostgreSQL prompt_versions 表
- 版本管理：每次创建新版本，保留历史版本
- 回滚机制：将指定版本内容复制为当前版本

### 4.5 模型配置模块

**功能描述**：平台级和租户级模型配置，支持多模型提供商、API Key 管理、默认模型设置。

**核心特性**：
- 模型提供商管理：平台管理员定义模型提供商（OpenAI、阿里云百炼、DeepSeek 等）
- 提供商配置：Base URL、API Key、模型列表、Embedding 模型
- 租户模型配置：租户使用自己的 API Key，独立计费
- 默认模型设置：设置对话默认模型、Embedding 默认模型
- 密钥加密存储：API Key AES 加密存储，不返显明文
- 密钥掩码显示：列表页只显示掩码后的 Key（sk-...xxxx）
- 平台默认模型：平台管理员配置默认模型，租户未配置时使用

### 4.6 租户管理模块

**功能描述**：平台管理员管理所有租户，支持租户创建、编辑、启用/禁用、密钥管理。

**核心特性**：
- 租户列表：查看所有租户，按名称、app_key、状态筛选
- 创建租户：自动生成 app_key/app_secret，设置租户名称
- 编辑租户：修改租户名称、状态
- 启用/禁用：禁用后租户无法登录、无法使用服务
- 密钥管理：查看 app_key，重置 app_secret
- 租户统计：查看租户工单数量、会话数量
- 平台管理员隔离：平台管理员账号不出现在租户列表中

### 4.7 认证鉴权模块

**功能描述**：基于 Token 的认证体系，支持 Token 签发、刷新、过期、黑名单。

**核心特性**：
- Token 签发：使用 app_key/app_secret 换取访问 Token（管理端登录支持 RSA-OAEP 加密 app_secret 传输）
- Token 结构：自研 HMAC-SHA256 签名 Token（非标准 JWT），载荷含 tenant_id、过期时间、随机 Nonce
- Token 刷新：刷新 Token 时旧 Token 自动加入黑名单
- Token 过期：默认 24 小时有效期，可配置
- Token 黑名单：Redis 存储（TTL 自动过期，多实例全局一致；查询失败按已拉黑处理）
- 登出功能：主动登出，Token 立即加入黑名单
- 登录防爆破：同一 IP+app_key 连续失败 5 次锁 10 分钟
- Nonce 唯一性：每次签发 Token 包含 16 字节随机 Nonce，确保唯一性
- 内部接口鉴权：Go ↔ Agent 内部接口使用 X-Internal-Token 鉴权

### 4.8 WebSocket 通信模块

**功能描述**：WebSocket 长连接，支持实时消息推送、AI 流式输出、人工客服实时通知。

**核心特性**：
- 长连接管理：Hub 模式管理所有 WebSocket 连接
- 用户端连接：用户通过 WebSocket 接收 AI 回复、人工客服消息
- 客服端连接：客服通过 WebSocket 接收新工单通知、新消息推送
- 流式输出：AI 回复通过 WebSocket 逐 chunk 推送
- 频率限制：单 IP 最多 10 连接、单 user_id 最多 3 连接、每秒最多 5 条消息
- 连接状态：实时监控连接数，Prometheus 指标暴露
- 断线重连：前端自动重连机制

## 5. 第三方集成

### 5.1 集成方式

| 集成方式 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| SDK 嵌入 (cs-chat.js) | PC 网站、H5 页面 | 轻量、可定制、无 iframe 限制 | 需要前端开发 |
| iframe 嵌入 (chat/pc.html) | 快速集成、无开发资源 | 简单、独立、升级方便 | 样式定制受限 |
| API 直接调用 | APP、小程序、深度集成 | 灵活、完全可控 | 需要自行实现 UI |

### 5.2 SDK 接入流程

1. **获取凭证**：租户管理员在后台获取 app_key/app_secret
2. **后端换取 Token**：第三方后端调用 `/api/auth/token` 接口，使用 app_key/app_secret 换取访问 Token
3. **前端引入 SDK**：在页面中引入 `cs-chat.js`
4. **初始化 SDK**：传入 Token、user_id、标题、主题色等参数
5. **用户对话**：用户点击客服按钮，弹出对话窗口，开始对话

### 5.3 Token 换取示例

```bash
# 第三方后端调用，换取 Token
curl -X POST http://your-domain.com/api/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "app_key": "your_app_key",
    "app_secret": "your_app_secret",
    "user_id": "user_123"
  }'
```

返回：
```json
{
  "token": "eyJ0aWQiOiJ0X2RlbW8iLCJleHAiOjE3ODg3NjU5OTQsIm5vbmNlIjoi...",
  "expires_in": 86400,
  "tenant_id": "t_demo"
}
```

## 6. 可观测性设计

### 6.1 日志体系

**结构化日志格式**：
```json
{
  "timestamp": "2026-09-06T10:50:57.031Z",
  "level": "info",
  "message": "HTTP请求完成",
  "method": "GET",
  "path": "/api/auth/tenants",
  "status": 200,
  "duration": 3,
  "trace_id": "05d8af59-836c-4d14-bbb9-aee10ffe97e3",
  "tenant_id": "t_demo",
  "client_ip": "172.24.0.10"
}
```

**日志收集链路**：
```
Go/Python 应用 → stdout (JSON格式) → Docker 日志驱动 → Promtail → Loki → Grafana 查询
```

### 6.2 监控指标

**核心指标**：
| 指标名 | 类型 | 说明 |
|--------|------|------|
| cs_http_requests_total | Counter | HTTP 请求总数（按 method/path/status） |
| cs_http_request_duration_seconds | Histogram | HTTP 请求延迟分布 |
| cs_websocket_connections | Gauge | 当前 WebSocket 连接数 |
| cs_active_sessions | Gauge | 当前活跃会话数 |
| cs_agent_calls_total | Counter | Agent 调用次数（按 endpoint/status） |
| cs_agent_call_duration_seconds | Histogram | Agent 调用延迟分布 |

**告警规则**：
- HTTP 5xx 错误率 > 5%（持续 2 分钟）→ 严重
- P95 请求延迟 > 3 秒（持续 2 分钟）→ 警告
- WebSocket 连接数 > 1000（持续 5 分钟）→ 警告
- Agent 调用失败率 > 10%（持续 2 分钟）→ 严重
- 服务宕机 > 1 分钟 → 严重

### 6.3 链路追踪

**追踪链路**：
```
用户请求 → Nginx → Go 网关 (span: HTTP 请求) → Python Agent (span: AI 对话) → 数据库 (span: 查询)
```

**trace_id 透传**：
- W3C TraceContext 标准格式
- HTTP Header：`traceparent`
- 响应头：`X-Trace-Id`
- 日志字段：`trace_id`
- Jaeger UI：通过 trace_id 查询完整链路

**采样策略**：
- 默认 10% 采样率（生产环境可调整）
- 错误请求 100% 采样
- 可通过环境变量 `OTEL_TRACES_SAMPLER_ARG` 调整

## 7. 安全设计

### 7.1 认证安全
- Token 签名：HMAC-SHA256 签名，签名密钥 = 租户 app_secret 的 sha256 哈希（存 DB，不存明文）
- Token 过期：默认 24 小时，刷新机制
- Token 黑名单：Redis 存储，登出、刷新后旧 Token 立即失效（fail-closed）
- 登录防爆破：Redis 计数，同一 IP+app_key 连续失败 5 次锁 10 分钟
- 暴力破解防护：WebSocket 频率限制（连接数 + 消息速率）

### 7.2 数据安全
- 多租户隔离：tenant_id 字段 + 中间件校验，防止越权访问
- API Key 加密：AES 加密存储，不返显明文
- 内部接口鉴权：Go ↔ Agent 使用 X-Internal-Token
- 知识库隔离：Qdrant 按租户独立集合

### 7.3 传输安全
- HTTPS：生产环境建议配置 SSL 证书
- WebSocket：WSS 加密传输
- CORS：可配置允许的域名

### 7.4 频率限制
- 单 IP 最多 10 个 WebSocket 连接
- 单 user_id 最多 3 个 WebSocket 连接
- 每秒最多 5 条消息（滑动窗口）

## 8. 部署架构

### 8.1 Docker Compose 一键部署

```bash
# 克隆项目
git clone https://github.com/myrockey/ai_customer_service.git
cd ai_customer_service

# 配置环境变量
cp .env.example ../.env
# 编辑 .env，配置大模型 API Key 等

# 一键启动所有服务
docker compose up -d --build

# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f go agent
```

### 8.2 服务端口映射

| 服务 | 容器端口 | 宿主端口 | 说明 |
|------|---------|---------|------|
| Nginx | 80 | 8080 | 前端 + API 入口 |
| Go 网关 | 8080 | - | 容器内部访问 |
| Python Agent | 8000 | - | 容器内部访问 |
| MySQL | 3306 | 3306 | Navicat 连接管理 |
| PostgreSQL | 5432 | 5432 | 数据库管理 |
| Qdrant | 6333 | 6333 | 向量数据库管理 |
| Redis | 6379 | 内网 | 登录防爆破/Token 黑名单/配置失效广播/索引队列（强制依赖） |
| Grafana | 3000 | 3000 | 监控可视化 |
| Prometheus | 9090 | 9090 | 指标查询 |
| Loki | 3100 | 3100 | 日志查询 |
| Jaeger | 16686 | 16686 | 链路追踪 UI |

### 8.3 数据持久化

| 数据 | 存储方式 | 备份策略 |
|------|---------|---------|
| MySQL 数据 | Docker Volume (cs_mysql_data) | 每天凌晨 2 点全量备份，保留 7 天 |
| PostgreSQL 数据 | Docker Volume (cs_postgres_data) | 每天凌晨 2 点全量备份，保留 7 天 |
| Qdrant 向量 | Docker Volume (cs_qdrant_data) | 每天凌晨 2 点集合快照，保留 7 天 |
| Redis 数据 | Docker Volume (cs_redis_data) | AOF 持久化；建议云 Redis 高可用（备份由云服务承担） |
| Loki 日志 | Docker Volume (cs_loki_data) | 自动保留 7 天 |
| Prometheus 指标 | Docker Volume (cs_prometheus_data) | 自动保留 7 天 |

## 9. 扩展性设计

### 9.1 水平扩展
- Go 网关：无状态设计，可多实例部署，Nginx 负载均衡
- Python Agent：无状态设计，可多实例部署
- WebSocket：需要粘性会话或 Redis Pub/Sub 实现多实例消息同步

### 9.2 模型扩展
- 模型提供商可配置：平台管理员定义新的模型提供商
- 支持 OpenAI 兼容接口：任何兼容 OpenAI API 的模型都可接入
- Embedding 模型可配置：支持多种 Embedding 模型

### 9.3 功能扩展
- 工具调用框架：LangGraph Tool 机制，可快速新增业务工具
- 中间件扩展：Go 中间件链，可快速新增鉴权、日志、监控等
- 插件化设计：Service 层抽象，可替换具体实现
