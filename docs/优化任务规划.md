## 🔴 P0 第二轮 — 上线前必做（风险/可靠性）

### P0-1：测试从零起步
- **现状**：全项目 0 个测试文件；CI unit_test 为 manual + allow_failure，形同虚设
- **方案**：
  - Go：token 签发/校验、租户隔离、工单状态机核心单测（service 层）
  - Agent：prompt 版本、知识库 chunk 工具函数单测
  - 部署后 API 冒烟断言（scripts/verify_*.sh 转为 CI 可跑形式）
- **状态**：✅ 已完成（Go auth 16 项 + Agent 5 项 + 健康冒烟 14 项；入口 `scripts/run_p0_tests.sh`）

### P0-2：管理端登录防爆破
- **现状**：admin 登录无失败限流/锁定
- **方案**：连续失败 N 次锁定 + 滑动窗口限流（内存计数，可扩展 Redis）；登录审计
- **状态**：✅ 已完成（5 次失败锁 10 分钟，key=IP:app_key，429 提示 + login_fail/login_ok 审计）

### P0-3：CORS 收紧
- **现状**：gin-contrib/cors 全放开
- **方案**：生产仅放行配置域名白名单；SDK 场景走服务端代理，客户端不直接跨域
- **状态**：✅ 已完成（CORS_ALLOW_ORIGINS env，默认仅 localhost:8080）

### P0-4：密钥管理梳理
- **现状**：.env 明文存 AGNES_API_KEY / DASHSCOPE key；AES 主密钥来源待确认
- **方案**：生产密钥注入（env/密钥服务），AES 主密钥轮换机制，.env 不入库
- **状态**：✅ 已完成（生产 PROD_MODE 强制 MODEL_KEY_ENCRYPT_KEY 否则拒绝启动；.env.example 脱敏为占位符；生产 compose 补 CORS/MODEL_KEY_ENCRYPT_KEY 注入）
- **遗留**：git 历史 commit c7fcb95 曾含真实 AGNES/DASHSCOPE key，**需在服务商侧轮换旧 key**

### P0-5：生产备份定时化
- **现状**：backup_all.sh 已写，但生产 compose 无 backup 服务、无 cron
- **方案**：生产部署包加 backup 服务（每日 MySQL/PG/Qdrant 备份 + 保留 N 天）
- **状态**：✅ 已完成（backup 服务：alpine + crond，BACKUP_CRON/BACKUP_RETENTION_DAYS 可配，容器直连模式已实测 MySQL/PG/Qdrant 三类产物）

### P0-6：部署后健康自检
- **现状**：部署包无自检
- **方案**：verify 脚本：容器健康 + 登录 + 核心接口断言，部署完成后自动执行
- **状态**：✅ 已完成（deploy/production/healthcheck.sh：6 步 14 项断言，含真实 AI 聊天冒烟；入口 `scripts/run_healthcheck.sh`）

## 🟠 P1 第二轮 — 产品化关键（计费/安全/数据）

### P1-1：Token 用量计量
- **现状**：无每租户 token 用量统计，无法计费
- **方案**：
  - Agent 会话级埋点：每次 LLM 调用记录 prompt/completion token
  - PG 建 token_usage 表（tenant_id/date/model/input_tokens/output_tokens）
  - Go 后台报表接口（按租户/按天聚合）+ 管理端用量页面
- **状态**：✅ 已完成

### P1-2：租户配额
- **现状**：无并发/QPS/存储/知识库容量上限，多租户可互相影响
- **方案**：tenants 表加配额字段（并发会话数、每日消息数、知识库文档数/容量），Agent/Go 双端校验，超限返回明确错误
- **状态**：✅ 已完成

### P1-3：审计日志
- **现状**：无后台操作审计，合规缺失
- **方案**：audit_logs 表（tenant_id/operator/action/object/before/after/ip），Go middleware 统一记录 Prompt/模型/租户/知识库变更；管理端可查
- **状态**：✅ 已完成

### P1-4：消息表归档策略
- **现状**：messages 无限增长，查询随数据量变慢
- **方案**：按月分区（或归档到 messages_archive），设定保留期；工单/会话列表查询走分区裁剪
- **状态**：✅ 已完成

### P1-5：SDK 版本化 + CDN 分发
- **现状**：cs-chat.js 裸文件无版本号，升级不可控
- **方案**：SDK 内部版本常量 + 构建产物带 hash + 版本化 URL（cs-chat@1.0.0.js），产品手册同步说明升级方式
- **状态**：✅ 已完成

### P1-6：会话清理确认
- **现状**：session_meta 过期回收逻辑在 agent，但未确认定时任务随启动运行
- **方案**：确认 agent 启动即注册清理任务（asyncio 后台任务），生产有回收日志；补确认脚本
- **状态**：✅ 已完成
